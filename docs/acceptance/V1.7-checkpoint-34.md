# V1.7 checkpoint-34：OpsPilot 自身服务指标到 Incident

日期：2026-09-23。状态：通过。服务指标规则和第十项 CI 门禁已加入；[Run 35855839535](https://github.com/Trigger726/OnCall-Agent/actions/runs/35855839535) 十项门禁全部通过。

## 目标与边界

checkpoint-33 从 Pushgateway 注入受控 gauge，验证了 Prometheus 规则链路，但没有使用真实服务指标。本轮直接抓取 OpsPilot 已暴露的 `/actuator/prometheus`，以 Spring Boot 自动采集的 HTTP 401 请求计数识别短窗口未授权访问突增，交由现有 Alertmanager receiver 创建并恢复同一 Incident 告警。Spring Boot [Metrics 文档](https://docs.spring.io/spring-boot/reference/actuator/metrics.html)说明 MVC 请求的 `http.server.requests` 指标与状态标签，Prometheus [函数文档](https://prometheus.io/docs/prometheus/latest/querying/functions/)说明 `increase()` 的计数器窗口语义。此规则是可复现的安全/运营信号演示，不宣称已完成业务服务的可用性 SLO 或生产告警调优。

## 可证伪验收

1. Prometheus `/api/v1/rules` 加载新规则，`up{job="opspilot"}` 为 1，并实际抓到 `http_server_requests_seconds_count{status="401"}`，不能仅凭应用返回 401 推断指标存在。
2. 十二次真实未授权 HTTP 请求使规则进入 `firing`，Alertmanager 向 OpsPilot 投递后只有一条 `FIRING:1` Alert。
3. 停止未授权请求，30 秒计数窗口清空后规则不再活跃，同一 Alert ID 变为 `RESOLVED:1`，恰有一条恢复时间线且无拒绝台账项。
4. 使用隔离 Compose project/volume 与运行时测试密钥，保存规则、抓取指标、规则状态、数据库终态和容器日志。脚本不直接调用 Alertmanager Alerts API 或 OpsPilot 成功接入 API。

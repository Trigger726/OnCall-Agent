# V1.7 checkpoint-13：GET SSE 与有界数据库补读

日期：2026-09-10。状态：本地全量通过，远端验证中。

## 接口与一致性

新增 `GET /api/v1/agent-runs/{runId}/events/stream`，使用现有登录权限，不改变 JSON `/events` 接口。查询参数 `after` 优先于 `Last-Event-ID`，省略时从 0 开始。非数字、负数、其他 run 的 ID、未存在 ID 返回 400；run 不存在返回 404，未登录返回 401。没有新增单 run 所有人/租户过滤，不能声称租户隔离。

先登记本地订阅，再从数据库按事件 ID 分页补读。Redis 标识事件只将对应 run 的订阅标记为需要补读，不使用通知 eventId 跳跃游标，也不把 Redis 正文发送给客户端。每个订阅串行处理，通知与读取交错通过 dirty 标志合并。每 5 秒对活跃订阅补读，适用于无 Redis、本地模式、通知缺失或 Stream 裁剪；当前是固定频率兜底，并未根据 Redis 恢复降低频率。

识别五类终态事件并关闭；客户端游标已指向终态时直接关闭空流。只基于事件事实判断终态，不因 run 状态先提交而提前截断终态事件。断开只移除订阅，不取消调查。60 秒连接周期到期、1000 个事件发送完后关闭，需要客户端携带最后处理的 ID 续订。

## 资源与边界

- 每实例最多 128 个 GET 订阅，超额返回 503/AGENT_SUBSCRIPTIONS_FULL。
- 独立 4 个发送线程、128 个排队任务；每订阅最多一个挂起/执行任务，通知合并不堆积任务。
- 一批最多读取 100 个事件，一条流最多发送 1000 个事件，也限制 emitter 初始化前的事件缓存数量；不是字节级大小限制。
- Redis 线程/补读调度线程不直接发送 SSE；执行器拒绝时不 caller-runs，保留 dirty 等待下次补读。
- 超时、错误、完成回调幂等释放本地订阅名额。IO 异常由 Servlet 完成响应，本地只注销。

[Spring MVC 异步文档](https://docs.spring.io/spring-framework/reference/web/webmvc/mvc-ann-async.html) 明确单次响应写入仍可能阻塞。本轮用阻塞 Output 测试证明通知线程和注销不等待发送锁，但**没有验证真实慢 socket 的写超时与线程释放**。慢连接仍可能占满 4 个发送线程；不能宣称已完成慢客户端全链路隔离。

## 业务规则与来源

参考 [Grafana OnCall 轮转 API](https://grafana.com/docs/oncall/latest/oncall-api-reference/on_call_shifts/) 的有序成员轮转与覆盖分层，本项目在现有普通班次/临时覆盖上增加自动续排，不替换种子班次，也不复制其 iCal、换班、多层和跨时区能力。

- V26 持久化不可变的锚点、班长与成员顺序，以及版本化续排状态；同一计划最多一条活跃轮转，创建/恢复/暂停都受 ADMIN/OPS_MANAGER 控制。
- 1–20 名不同成员、每班 60–10080 分钟；锚点为整分钟，创建时距数据库现在最多 31 天。时段序号由锚点与当前数据库会话时间计算，成员取 `slot % memberCount`，边界 `[start,end)`；重启、重复扫描不从第一个成员重新开始。
- 创建立即物化覆盖当前至未来 14 天开始的班次，后续默认每分钟自动续排。单班可能延伸到查询窗口外；不做无限历史回补，单轮每条规则最多 512 个时段、最多扫描 100 条轮转。
- 一致的 `schedule -> rotation -> user` 锁序串行化冲突写入，用户按 ID 顺序锁定；台账主键 `(rotation_id,slot_index)` 和班次唯一来源 `(rotation_id,rotation_slot)` 防重。
- 不覆盖已有普通班次，受阻时段记 `BLOCKED`；不跳过停用/无运维职责成员偷偷换人，记 `MEMBER_UNAVAILABLE`。这些未生成时段在之后的扫描可重试；已生成班次一旦显式取消，原时段永不自动重建。
- 生成事实与当前资格分开：既有生成行不会因账号资格改变重分配，但接口返回 `memberAvailable`，扫描保留警告；当前值班与 ON_CALL 路由均排除已撤销运维职责的用户。
- 暂停只停止继续生成，已生成班次、覆盖和取消历史保持不变；若要撤销已有班次，仍走 V25 的版本化取消。规则本体不编辑，变更需暂停旧规则后创建新规则，已有重叠不会被静默抹掉。
- 每条规则一个独立 READ_COMMITTED 事务；一条生成失败全部回滚、记录失败 ID/告警，其他规则仍继续。自动生成按系统/scheduler 审计，手动触发保留真实操作者。

## 接口与部署

`GET/POST /api/v1/on-call/rotations`、`GET /{id}`、`GET /{id}/slots`、`POST /{id}/state`、`POST /scan`。只读角色可查询，不可创建/变更/扫描。列表最多 100 条、时段窗口最多 31 天/200 条，两者有显式截断标志；详细规则可按 ID 回读。

默认后台扫描间隔/初始延迟均为 60000ms，可用 `ONCALL_ROTATION_ENABLED`、`ONCALL_ROTATION_SCAN_DELAY`、`ONCALL_ROTATION_INITIAL_DELAY` 配置。未配置轮转时空扫描，不改变现有 Demo。沿用当前数据库会话本地时间，要求会话时区保持固定；计划的历史 timezone 字段仍不参与换算，不能宣称已经支持跨时区/DST。

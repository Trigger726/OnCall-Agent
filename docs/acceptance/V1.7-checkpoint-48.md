# V1.7 checkpoint-48：日历覆盖、缺班与有效路由预览

日期：2026-09-27。状态：最终日历本地验收通过，远端 CI 待补证。整体目标仍 active。

## 为什么做这一轮

checkpoint 43 的班次维护和 46 的轮转台账只能看“存在什么班次”，不能直接回答整段窗口有没有可路由的人。参考 [PagerDuty Schedule Basics](https://docs.pagerduty.com/incident-management/schedules/schedule-basics) 的最终排班预览和缺班表达，新增已持久化班次的日历覆盖，而非复制其所有层级、通知或时区机制。OpsPilot 的实际路由优先级仍是自己的已有规则。

## 实施与边界

- `GET /api/v1/on-call/coverage?scheduleId=...&from=...&to=...`，所有已认证角色可读；默认从当前数据库会话时间起 7 天，窗口须为正且最多 31 天。不存在计划 404、坏窗口 400；没有写入、生成任务或额外审计。
- 在只读 REPEATABLE_READ 事务里读取计划和用户/班次快照；将窗口首尾和班次起止点切成连续半开区间。按覆盖优先、开始时间倒序、ID 倒序选一个有资格的活跃用户，与 `current()` 和 ON_CALL 路由一致。
- 取消不参与；无资格覆盖回退到有效普通班。计划停用整段记缺班；未排班、成员不可用分别解释。被遮盖 ID、无资格 ID、历史同层重叠显式展示，不把多个候选重复累计覆盖。
- 最多读取 1001 条未取消源班次，超过 1000 返回 409 `ONCALL_COVERAGE_TOO_DENSE`，不输出截断的健康结论。只查询一次候选，在有界集合内分段，不逐区间查数据库。
- 页面有逐日日历、单日选择/所有日期、有效时间线、只看缺班、源班次引用与完整窗口的覆盖/缺班小时数；时间线先展示 50 段，可继续展开，汇总始终基于服务端完整结果。
- 跨午夜按日裁剪；UTC 只作为无时区日历算术载体，展示和查询保留原始数据库时钟，不把它转换为浏览器瞬时。闰日/结束午夜不重复计算。不支持跨时区/DST，不能把这项当成此能力已完成。
- 普通维护/轮转变更会刷新预览；查询加载/失败先移除旧结论，加载期间禁止修改筛选。并发刷新请求排队重算，避免变更通知丢失。
- 未来覆盖仅说明已落库班次及当前成员资格，不预测未生成轮转，不保证未来账号资格；过去窗口也不是历史资格快照。这里不是可用性 SLO，不是通知回执或人工接单。

## 首次远端失败与修正（证据保留）

代码 `b1091f5` 的 [Run 36270725862](https://github.com/Trigger726/OnCall-Agent/actions/runs/36270725862) 三份浏览器脚本全部退出 0，但 runner 检测到真实 JAR ERROR 后判 FAIL、镜像门禁按依赖跳过；其他十项门禁成功，不能称十二项全绿。ZIP 已下载核验 SHA256，结果保存在 [首次失败](assets/V1.7-checkpoint-48/first-ci-failure.json)。

实际日志第一类为导航断连的 Tomcat `ClientAbortException: Broken pipe`，发生于 JSON 响应 flush，不是覆盖数据计算错误。全局异常处理新增仅匹配该容器类型的独立分支：DEBUG 单行、不再向死连接写 JSON，未提交响应仅置服务端诊断 499，已提交响应不改；普通 IO/外部 Provider 的 Broken pipe 仍走真实 500，不能只靠异常消息隐藏错误。参考 [Spring 断连分类说明](https://docs.spring.io/spring-framework/docs/6.1.20/javadoc-api/org/springframework/web/util/DisconnectedClientHelper.html)，本轮使用更窄的已观察 Tomcat 类型，而非广泛消息匹配。四项回归覆盖处理器选择、空体、已提交不改和 Provider IO 不误吞；不是强制真实 socket 故障矩阵。

第二类为 JVM 停机时 H2 自动关闭 hook 与 200ms 后台扫描竞态，产生 90135/90121。只对验收 runner 的唯一内存库设置 `DB_CLOSE_ON_EXIT=FALSE`，避免 H2 的独立 hook 抢先关闭；日常文件库/生产 URL 不改。内存仍随自有 JVM 退出消失。runner 进一步在自有 JAR 完全退出后扫描完整日志，将停机错误也计入失败，而非只验运行阶段；新增严格日志回归，不降低门禁。

修正后的本地与 Linux 结果待后续补证，不用首次 UI 断言通过冒充总门禁通过。

修正后本地 UTC 全量/JAR 与三份浏览器流程已重新通过；4 项断连回归和生命周期 9/9 通过。完整停机后 `unexpectedJarErrors=0`，证据：[修正后 runner](assets/V1.7-checkpoint-48/local-fixed-runner-result.json)。Windows 的进程停止行为不冒充 Linux 正常关闭 hook，远端仍需单独证明。

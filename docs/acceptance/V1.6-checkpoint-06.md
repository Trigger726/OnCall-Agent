## 3. 设计取舍

### 3.1 为什么是载荷擦除而不是整行 DELETE

检索快照已被相关性判断、复核、审计和离线评测引用。直接物理删除整行会破坏外键和证据链，因此 V12 把有保留期的敏感载荷与需要长期保留的结构事实分开：

- 擦除 `query_text`、可反查原文的 `query_hash`、`results_json` 和 `created_by`；
- 清空判断自由文本，自动终止到期未复核项；
- 保留快照 ID、引擎、耗时、状态、时间和脱敏计数；
- 保留复核时已复制出的脱敏 qrel。

这不是软删除后仍保存原文；墓碑替换会不可逆覆盖在线主库载荷。它也不是对全数据链路删除的夸大声明，备份和导出副本仍列入后续。

### 3.2 参考依据

[OWASP Logging Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html) 建议敏感数据不应直接记录，应在记录前移除、掩码或脱敏，并按要求处理日志保存期限。[Grafana Loki retention](https://grafana.com/docs/loki/latest/operations/storage/retention/) 展示了由 Compactor 定时执行、按保留策略批量处理的运维边界。OpsPilot 借鉴的是“写前清洗 + 定时批处理 + 幂等状态”的原则，不宣称复刻其存储架构。

## 6. 诚实边界与下一步

1. 当前擦除范围是在线业务主库；备份、CDC、数据仓库和人工导出需要同等策略与可验证的销毁流程。
2. 默认 30 天是工程默认值，正式部署必须由法律、合同和安全要求确认，不能把示例配置当合规结论。
3. 当前所有角色共享同一保留期，尚未按租户、数据类别或地区差异化。
4. 还没有面向单个用户/单条快照的受控删除申请与审批流程。
5. 脱敏依赖规则匹配，不能代替源系统少采集、字段白名单和数据分类分级。
6. 下一检查点优先获取真实但脱敏的查询样本，按频率和故障类型分层评测；同时升级 Flyway 并验证备份/导出删除策略。

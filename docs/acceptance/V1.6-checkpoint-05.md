## 3. 设计说明

### 3.1 待办盲化

管理员或运维经理打开待办时，服务端从不可变 `results_json` 快照中提取：

- 查询原文；
- 当时返回的文档标题与摘要；
- 稳定引用；
- 实际检索引擎和创建时间。

接口不返回提交人的姓名、原始 0–3 级或评论。前端无法靠隐藏 DOM 恢复这些字段，盲化发生在服务端响应边界。复核完成后的审计记录会同时保留提交等级和复核等级，便于追责。

### 3.2 最终等级策略

- `APPROVE + reviewerGrade 2/3`：以复核等级生成正相关 qrel。
- `APPROVE + reviewerGrade 0/1`：保存双评分用于误召回和一致性分析，但不生成“预期命中”。
- `REJECT`：表示样本/流程本身不应采用，不要求编造第二等级，也不参与一致性。
- 同一 query-document 若以后产生多个已批准最终等级，V10 评测器继续取均值。

该策略不引入 `DISPUTED/ADJUDICATING` 等新状态；当前样本规模不足以证明需要第三方仲裁工作台，先保留可观测分歧，待真实数据出现后再扩展。

### 3.3 一致性公式

四级标签是序数数据，因此使用线性不一致权重：

```text
weight(i, j) = |i - j| / 3
kappa = 1 - observedWeightedDisagreement / expectedWeightedDisagreement
```

同时保留：

- 精确一致率：两个等级完全相同的样本比例。
- 相邻一致率：两个等级相差不超过一级的样本比例。
- 样本数：避免只展示一个脱离规模的 κ。

定义参考 [scikit-learn `cohen_kappa_score`](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.cohen_kappa_score.html)：Cohen's kappa 用于两名标注人，可选择线性权重，取值通常在 -1 到 1；当期望分歧为 0 时指标未定义。OpenSearch 也把 judgment 定义为 query-document 评分，并将分级评分用于 NDCG 等指标：[OpenSearch Judgments](https://docs.opensearch.org/latest/search-plugins/search-relevance/judgments/)。

## 6. 未通过项与诚实边界

1. 本机 `dockerDesktopLinuxEngine` 不存在，MySQL 8.4 没有直接执行 V11；H2 兼容模式不能替代该证据。
2. κ 只适用于当前两名标注人的设计；超过两人不能直接沿用。
3. 当前没有第三方仲裁。复核评分作为最终等级是明确的治理规则，不代表提交人一定错误。
4. 集成测试中的 κ `0.727273` 只验证公式和 API，不代表真实标注团队水平。
5. 查询原文和结果摘要仍缺少自动保留/删除、字段级脱敏和部门级数据范围。
6. 真实 DashScope Embedding 与 cross-encoder rerank 仍无直接质量对照证据。
7. 前端已通过类型检查和生产构建，本检查点没有新增登录后桌面/移动端浏览器截图；数据与权限行为由 MockMvc 和最终 JAR API 证明。

# V1.7 checkpoint-18：刷新后自动接回运行中的调查

实施日期：2026-09-14；远端证据复核日期：2026-09-16。状态：实现、13 项前端测试、构建、真实浏览器新旧对照及六项 CI 门禁通过。

## 用户可见变化

Incident 工作台与 OnCall 助手加载服务端详情后，发现 QUEUED/RUNNING 调查即 GET 订阅同一 run。刷新不再要求再次点击“运行”，不会自动 POST 创建调查。刷新后的页面没有旧事件列表，因此从数据库游标 0 重建轨迹；当前连接中断仍从最后成功处理的事件游标续订。这不是把业务事件正文缓存到浏览器，也不承诺跨刷新只取增量。

OnCall 助手将选中会话记录到 `?session=<id>`，重新加载先使用有效会话编号；从 Incident 的 `?incident=<id>` 进入后转换为会话 URL。切换 Incident/会话、删除会话、离开页面会中止旧订阅，返回后重新挂接仍在运行的调查。过期详情响应通过选择版本号丢弃，旧订阅完成回调不得清理新订阅。刷新后的终态只显示服务端已完成详情，不重复订阅。

`subscribeAgentInvestigation` 是 GET-only 入口：不创建幂等键，不将失败订阅转换为 POST，沿用有限重试、事件归属校验、游标去重、终态停止和 AbortSignal。刷新恢复失败保留后台任务，不隐式取消。浏览器关闭前 POST 结果完全未知时的自动发现不保证成功，仍保留已有手动幂等重试语义。

## 发现与修复

初版只接入自动 GET 时，真实 Edge 153 + Vite 代理中出现等待响应头、运行中 10 秒未显示 LIVE 的失败；直连后端和代理的命令行客户端可读到 SSE。显式增加 `Accept: text/event-stream` 后，同一测试路径能在调查闸门未释放时显示 STREAMING。单元测试增加 POST/GET 均声明该 Accept 的断言。此处记录观察到的请求差异与修复后证据，不推断未经验证的浏览器内部实现原因。

最终刷新不需要持久化新的前端 run 缓存：服务端详情是活动 run 的事实源，URL 只保存当前导航位置。保持既有全局登录可见性，未新增租户隔离或 run 所有者权限。

- 按 frontend-testing-debugging 技能执行实际页面检查。Browser plugin not available，使用已安装 Playwright 1.62.1 / Edge 153，无新增浏览器依赖。

- 后端是独立内存 H2、AI 关闭，使用已存在的 test-classpath DistributedAgentNode 只读闸门工具；调查停在工具步骤时刷新，确认 LIVE 后才释放文件闸门。不是生产 JAR 双实例或真实 provider 验证；不会修改用户数据库。
- 桌面 1440×1000：实际点击启动 → 等待服务端闸门 → 刷新 → 同 run GET 回放 → 切换上下文清理旧面板 → 返回再次接回 → 释放工具 → 终态。每页只能有一次调查 POST，刷新和返回分别只能 GET。

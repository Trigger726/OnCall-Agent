# V1.8 CP06：真实 MySQL 的范围评测与 V43 升级

## 本轮边界

接续 CP05 尚未验证的 MySQL 兼容性。本轮仅新增测试入口、隔离运行脚本和证据，不修改生产 Java、V1–V43 迁移、前端、排序算法或历史 Demo。

当前状态：真实 MySQL 8.0.41 与 H2 的 16 项共享契约连续两次通过；脚本最终版正常关闭临时 MySQL，端口释放。默认未启用专项时 8 项 MySQL 场景全部跳过，无数据库连接。

## 实现

- H2 和 MySQL 继承同一 `ScopedEvaluationScenarios`，原 7 个断言场景不复制、不删减；每个业务场景事务回滚。
- 两种数据库调用同一非空 V42→V43 升级断言：旧查询载荷、标签、enabled、V1–V42 校验和不变，CONSOLE 标记 GLOBAL，历史 ASSISTANT 标记 UNKNOWN，重复迁移执行 0 项。
- MySQL 入口必须显式启用 `opspilot.scoped.eval.mysql.enabled=true`，数据库连接只来自专用环境变量，没有现有数据库地址或密码默认值。
- 原生脚本创建全新临时数据目录，忽略机器默认配置，随机可用端口、只绑定 127.0.0.1、关闭 MySQL X 监听和 Windows 监护子进程；启动后立即为临时 root 设置随机密码。
- 不安装软件、不操作现有 MySQL 服务、不执行 DROP/clean，不删除临时数据库；正常结束使用认证后的 mysqladmin shutdown，仅在超时后终止自身持有的子进程。

遵循 `karpathy-guidelines`：复用既有断言，只补本轮缺失的真实数据库证据，不扩展产品功能。

## 首轮失败保留

首轮 `opspilot-scope-mysql-5nCsga` 在测试前失败：mysql 批处理转义 Windows 反斜杠，使数据目录身份断言失败；mysqladmin 不支持 mysql 客户端的 `--batch` 参数；Windows 默认监护进程使仅停止启动器不能关闭服务进程。

修复脚本：使用 `--raw`，分开客户端/管理命令参数，使用 `--no-monitor`。首轮孤立服务进程通过 PID、完整数据目录及端口核对后终止；没有停止现有服务。首轮 0 项产品场景执行，不把它说成生产缺陷。

## 可重复执行

Windows 已安装 MySQL、JDK 21、Maven且依赖已缓存时：

```powershell
& 'D:/Node/node.exe' scripts/verify-scoped-evaluation-native-mysql.cjs `
  --mysql-home 'C:/Program Files/MySQL/MySQL Server 8.0' `
  --java-home 'C:/Program Files/Java/jdk-21' `
  --maven 'D:/tools/apache-maven-3.9.16/bin/mvn.cmd' `
  --m2 'D:/Codex/国网/tmp/m2-repository'
```

生成目录会打印到标准输出；包含 qa.json、四份 JUnit XML、Maven/初始化/服务/停止日志及保留的临时数据库。Maven离线执行，无外部模型请求。只复用两个专用 schema，不接受现有数据库地址作为脚本参数。

初始化及停止方式参考 [MySQL 官方初始化说明](https://dev.mysql.com/doc/refman/8.0/en/data-directory-initialization.html)、[Windows 命令行启动/停止](https://dev.mysql.com/doc/refman/8.0/en/windows-start-command-line.html)。初始无密码只用于新建的短时 loopback 测试实例，不能用于部署。

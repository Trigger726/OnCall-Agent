日期：2026-09-18。状态：通过。GitHub Actions Run 52 的真实容器故障门禁已证明 Tempo 短暂停机不影响调查业务，Collector 在有界重试内完成 Trace 恢复。V1.7 整体仍在持续迭代。

本地静态证据：`bash -n scripts/verify-tracing-pipeline.sh`、`docker compose --profile tracing config --quiet` 与 `git diff --check` 均通过。

## 本轮目标

checkpoint-22 已证明正常链路可以将 Agent trace 经 Collector 写入 Tempo，但尚未证明后端短暂不可用时的业务隔离和恢复。本轮仅验证已配置的 60 秒有界重试窗口，不扩大为任意故障或零丢失承诺。

## 可证伪验收契约

1. 先通过 checkpoint-22 的正常 TraceQL/Grafana 读回契约。
2. 明确停止 Tempo 容器，再提交带动态敏感哨兵的告警并执行六工具调查。
3. Tempo 不可用期间，调查必须返回 `COMPLETED`，OpsPilot 健康必须为 `UP`。
4. Collector 日志必须出现真实导出失败，避免“停了后端但没有 telemetry”的假故障。
5. 在 60 秒重试窗口内重启 Tempo，必须能按同一 run ID 读回 `1/6/2` span、正确父子层级，且 trace 不包含动态敏感哨兵。

## 边界

- 该门禁验证 Tempo 短暂故障，不验证 Collector 进程或宿主机重启。
- 当前 sending queue 是内存队列；Collector 退出后不保留队列，因此不声明持久化或零丢失。
- 队列满载、超过重试窗口、持久队列、Tempo 高可用和对象存储仍待后续设计与容量验证。

# OpsPilot V1.7 检查点 08：实时推送故障隔离

## 问题与复现

2026-09-07 新增失败测试，2026-09-08 继续完成修复。afterCommit 中 sink 的运行时异常仍会传播到业务调用方，也会中断同一事务后续回调。旧版同事务记录两个事件，首个 sink 抛出 IllegalStateException 后，测试直接报错；实际数据库提交已完成，不能将推送失败当作持久化失败。

## 实现

仅在提交后的 sink 调用边界捕获 RuntimeException，保留已提交事件并允许后续回调继续。日志记录 run ID、event ID 与异常类型，便于按数据库事实回放定位；不输出异常自由文本或事件正文。序列化、SQL、事务提交本身的错误仍按原流程向上传播。

## 验证与 Demo 对照

保留 checkpoint-07 的提交/回滚演示，新增两个故障注入场景：同事务首个 sink 故障但第二个仍收到事件，两条记录均可回放；完整调查所有实时发送都抛异常，最终仍完成并生成报告，回放结束于 RUN_COMPLETED 且没有因推送产生的 STEP_FAILED/RUN_FAILED。旧版第一个故障中止调用，新版从事实源恢复结果。

`mvnw -B -Dtest=AgentEventTransactionIntegrationTest test` 共 4 项通过、0 失败、0 错误、0 跳过，包含原有提交与回滚用例。

# V1.7 checkpoint-16：Redis 暂停期间双实例补读与恢复补投

日期：2026-09-12。状态：测试已实现/编译，真实故障场景待 CI 验证。

## 故障场景

在 checkpoint-15 的两个独立 JVM + MySQL 8.4 + Redis 7.4 真实 HTTP SSE 测试上保留正常广播用例，并新增 Redis outage 用例。A 的只读工具等待两端订阅建立后，Docker pause 冻结本测试 Redis 容器，确认 inspect 状态为 paused。记录两端既有接收失败计数，等待 A、B 各产生新的 Redis 接收失败日志，再放行 A 的调查，避免用启动期间的旧错误冒充本次故障。

故障用例开启 500ms 数据库补读（仅加速测试；生产默认仍 5 秒），正常广播用例仍将初次/后续补读延后到一小时。Redis 保持暂停期间，A、B 都必须收到 RUN_COMPLETED，事件集与数据库完全一致且无重复；此时 outbox 非 DELIVERED 数须大于 0，证明仍有待补投事件。

随后 unpause Redis，不重启 Web 实例、不手动调用 relay/receiver、不改 outbox 状态，等待生产调度器自动将该 run 的待投递记录排空。真实读取 Redis Stream，确认包含数据库中的全部事件 ID；允许通知重复，不承诺 exactly-once。B 使用中间游标续订仍须只返回余下事件。

暂停对象仅限 Testcontainers 创建的 Redis；资源 finally 保证解除暂停，子进程仍按原用例独立清理。两个场景使用独立文件闸门和日志目录，历史 checkpoint-15 结果不覆盖。

## 证据与验收口径

`DistributedAgentEventsIntegrationTest` 现在包含 2 项条件测试。默认未开启 Docker 测试时两项均跳过，不能据此判定故障恢复通过。运行命令沿用 `./mvnw -B -Dopspilot.distributed.it.enabled=true -Dtest=DistributedAgentEventsIntegrationTest test`，继续由独立 CI 门禁执行。

每个 result.json 增加 redisPausedDuringCompletion、pendingOutboxDuringPause、pendingOutboxAfterRecovery 和 redisPublishedEventIds；同时保留两个 PID/端口、数据库/A/B 三份事件列表和恢复游标。正常广播与 outage 两份结果都必须检查。

本地已完成编译与条件发现（2 项跳过）；远端结果待补录。本轮不改生产事件分发代码，不新增浏览器截图；保留 checkpoint-14 实页 Demo 和 checkpoint-15 正常双 JVM 对照。

## 尚未覆盖

Docker pause 模拟 Redis 无响应与命令超时，不等同于断电、数据丢失或 Redis 重启；没有覆盖 Stream 清空后 ID 回退、裁剪缺口、执行 JVM 崩溃后的任务接管、真实慢 socket 资源释放和浏览器跨实例故障恢复。本轮只证明所测故障模型，完整分布式故障矩阵仍未完成。

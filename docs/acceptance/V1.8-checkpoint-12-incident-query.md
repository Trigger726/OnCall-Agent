## 已确认问题与范围

Incident 页固定请求 `size=100`，只显示本页长度为“记录数”，既无关键词搜索也无翻页；后端已有分页，但排序同时间无稳定 ID 次序。筛选请求没有列表级迟到响应围栏，可能倒序覆盖新筛选。列表越长，手机详情越难到达。

目标：后端按编号/标题/资源名称进行参数化字面子串搜索；保留原筛选与旧调用，返回真实总数和稳定分页。页面加显式搜索、清除、分页、错误重试与列表请求围栏，不改变处置、审批、Agent 或数据库结构。

按 frontend-design 沿用 MiSans、白 #fff/正文 #171717/次级 #636363/边线 #dedede、既有深色 token；不用新字体、渐变或装饰卡片。左对齐布局：`关键词与筛选 → [有界队列＋真实总数＋翻页 | 原处置详情]`，手机垂直排列但队列独立滚动，输入框/按钮保证可用。按 karpathy-guidelines 限定两处后端源文件与事件页；按 frontend-testing-debugging 用既有 Playwright，Browser plugin 不可用。

保留所有旧包、独立 Demo 和未提交改动。后续逐项记录真实测试与新旧同数据比较，不声明完整项目完成。

## 实现与本机验收

后端新增可选 `q`，按编号、标题或资源名称做参数化字面子串匹配；空白视为无搜索，超过 120 字拒绝。`%`、`_`、引号不作为通配符或 SQL 执行。原四参数服务调用保留；分页排序追加 ID 作为同严重度/同时间的确定性顺序，offset 使用 long，避免大页数溢出。没有把静态题集的顺序稳定声称为持续更新数据中的快照一致性。

前端默认每页 20 条，以后端 total 显示真实总数；搜索回第一页，保留严重度/状态筛选、清除、显式重读。AbortController、列表版本和登录 token 共同丢弃迟到响应，详情仍受已有 selectionVersion 围栏控制。列表加载时详情暂不可操作；换筛选仅断开旧 Agent 传输，不发送服务端取消命令，释放它对应的本地忙标记，保留原显式取消入口。

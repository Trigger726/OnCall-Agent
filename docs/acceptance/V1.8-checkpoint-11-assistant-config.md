## 实际缺口与限定设计

原始 OnCall 归档 `0cd654e` 的 `static/app.js` 未找到网页密钥编辑逻辑，配置在后端 `application.yml`；现版也只有 `DASHSCOPE_API_KEY` 与 `AI_ENABLED` 部署配置，而助手页仅显示模式，无法发现配置位置。没有证据证明曾有可直接填 Key 的设置页，不虚构“恢复旧页面”。

另发现当前根 `docker-compose.yml` 将 `AI_ENABLED` 写死为 `false`，即使环境变量或 `.env` 写 true 也不生效。本轮改为 `${AI_ENABLED:-false}`，保持默认离线，允许显式开启；不改应用 YAML、密钥值、依赖、数据库或 Java 业务。

使用 `frontend-design`，沿用 MiSans、白底 #fff / 正文 #171717 / 次级 #636363 / 细边线 #dedede 与既有暗色 token；输入框下常驻“模型与 API”入口，原模式状态保留。原生对话框按“当前模式、变量、对应文件、生效步骤”排列，不新增导航/装饰卡片/动效。使用 `karpathy-guidelines` 限定范围，按 `frontend-testing-debugging` 实页验证；Browser plugin 不可用，复用现有 Playwright/Chrome。

这是**部署配置说明入口，不是在线密钥编辑器**。无密钥输入、读取、保存、浏览器持久化或模型测试请求；没有把“已配置”冒称服务可用，也不把这个入口当作完整凭证管理已完成。在线编辑若后续明确实施，仍须设计管理员授权、凭证安全存储、审计/替换与多实例生效机制。

## 已实现行为

- 空对话与已有对话均有可点击入口；手机触控高度 44px。原生 modal 有标题、初始关闭焦点、Escape 和原触发按钮焦点返回；真实换账号时关闭，避免旧模式留屏。
- 规则模式明确未启用云模型；模型模式说明只反映页面加载时配置、不证明密钥/额度/可用性；读取失败显示待确认，不伪造规则模式或具体型号。
- 直接给出 `src/main/resources/application.yml`、两条绑定和 `.env.example` 位置，区分直接 JAR 启动与 Compose 插值，说明重启/重建容器与源码重新打包。环境变量和外部配置的机制参考 [Spring Boot 外部配置](https://docs.spring.io/spring-boot/reference/features/external-config.html)及 [Docker Compose 变量插值](https://docs.docker.com/compose/how-tos/environment-variables/variable-interpolation/)，结合本项目实际绑定核对，不宣称 `.env.example` 自动生效。
- 首轮页面测试通过后，人工查看手机截图发现关闭按钮会随内容滚走。保留首版 QA/截图/JAR；最终使用固定标题栏，新增滚到底部仍能点击关闭的断言。没有把首版截图替换成最终成功证据。

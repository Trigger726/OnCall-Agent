# OpsPilot V1.7 检查点 07：事务提交后的事件推送

## 问题与失败证据

2026-09-07 检查 `AgentRunEventService.record` 发现，默认 TransactionTemplate 会加入调用方已有事务；内部 execute 返回不等于外层事务已提交。旧实现随后直接调用 sink，可在外层回滚后留下客户端已接收、数据库无法回放的事件。

新增 `AgentEventTransactionIntegrationTest` 两项测试，旧实现均失败：提交前接收列表已非空，回滚后接收列表也非空。测试使用真实 H2/Flyway 与 Spring 事务，不依赖模拟提交回调。

## 实现与验证

在插入事务中注册 afterCommit 回调，实际事务提交成功后才调用 sink。外层回滚不会推送，事件行与 next_event_sequence 更新一起撤销。无外层事务时仍在 record 返回前推送。

定向执行事件事务与取消竞态两类集成测试，共 3 项通过、0 失败、0 错误、0 跳过。断言覆盖外层提交前无事件、提交后一次推送、游标回读同一事件 ID、回滚无推送/无新增行、回滚后序号复用，以及正常取消终态。

## 历史 Demo 与新版对照

代码提交 `25b4eec` 的 [CI 34107126144](https://github.com/Trigger726/OnCall-Agent/actions/runs/34107126144) 四段全部通过：前端 17 秒、H2/JAR 52 秒、MySQL 53 秒、容器健康烟测 1 分 11 秒。默认后端 44 项，0 失败、0 错误、2 项 MySQL 条件测试跳过；MySQL 由独立门禁执行。

保留 V1.4 的事件落库/回放演示。在工程演示中用外层事务包住 record，再主动回滚：旧版 sink 收到事件但回放查不到；新版 sink 不收到事件。提交对照则在提交结束后收到一次且可按 ID 回读。

## 范围与后续

afterCommit 不保证进程在提交后崩溃时仍能实时投递；数据库回放仍是恢复路径。Redis Streams/Kafka、持久化投递重试与跨实例订阅尚未实现，本检查点不宣称分布式事件交付完成。

# V1.7 checkpoint-40：固定集检索评测历史与口径隔离

日期：2026-09-25。状态：部分通过；本地 H2/API、前端测试与生产构建、打包 JAR 和桌面/390px 浏览器实页已通过，真实 MySQL 与远端 CI 待验。

## 问题与口径

此前 Runbook 页面只有最近一次离线评测，以及原版 contains、BM25、Hybrid 的当前对照。评测运行已持久化，但无法回答“在同一套 qrels 上，检索质量是否随版本变化”。另一方面，线上检索快照只允许对返回的文档做选择性人工复核；用这些稀疏、带选择偏差的反馈计算“生产命中率”会误导读者。

本轮新增最近 12 次固定集评测历史，保留运行时间、实际引擎、数据集版本、查询/qrel 分母、Recall@3、MRR、NDCG@3 和首位稳定引用命中率。只有相邻两次运行的数据集版本和实际引擎都相同，才显示 Recall@3 的百分点变化；不同版本或引擎的行显式标注不同口径，不串成同一趋势。无运行时展示空状态，不填充种子百分比。历史迁移前缺失的 `judgment_count` 回退到查询数，缺失的 NDCG 保持 `N/A`，不会伪造老结果。

这种固定查询集与人工相关性判断的评测方式可与 [Elasticsearch Ranking Evaluation](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/search-rank-eval) 和 [OpenSearch Query Sets](https://docs.opensearch.org/latest/search-plugins/search-relevance/query-sets/) 对照；OpsPilot 目前仍只有小规模种子集和少量受控人工判断，不声称生产检索准确率。

## 后续边界

需要从真实但脱敏的查询流量构建有代表性的查询集，并补充分层、偏差评估和足够规模的双评分，才能讨论生产相关性趋势。本检查点仅让既有离线评测可追溯、可比较，不提供线上 A/B 实验或实际用户满意度估计。

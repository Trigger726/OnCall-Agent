## 解决的问题

- **资源台账可以持续维护。** ADMIN、OPS_MANAGER 可登记和编辑服务、环境、负责人、状态及说明。资源编码统一大写、登记后不可改，保证告警关联稳定；编辑使用版本冲突保护。有效负责人、当前角色和会话在事务内复核，写入与操作者审计一起提交或回滚。ON_CALL/AUDITOR 不能写。未增加删除入口，原依赖、属性及历史关联保留。
- **资源超过 100 条仍能找到。** 搜索和分页由服务器处理，显示真实总数；`%`、`_` 按字面搜索。迟到的列表/详情和换账号前的结果不能覆盖当前内容。保存后定位实际资源；可带服务名称进入事件搜索。
- **首页故障不再连带清空全部信息。** 指标、事件、排班分别读取，某一接口失败时清除该部分旧数据，其他成功结果可继续查看。事件队列明确包含已恢复事件，资源状态明确来自台账。
- **告警页补齐可恢复状态。** 正常告警按 20 条分页，读取失败与拒绝台账失败分别提示；重放异常可见，同一页面防止重复在途提交。损坏的本地登录缓存不会造成白屏；审计导航按角色显示。
- **页面更紧凑且加载更轻。** 使用 frontend-design 和 frontend-testing-debugging skill，在既有 OKX 黑白/黄绿、MiSans、浅深主题和自动流光基础上调整层级。首页标题区高度缩减，资源页采用查找/详情双栏，手机改纵排，编辑弹窗底部操作区保持可见；导航支持 Escape 和焦点恢复。11 个页面改为按路由加载。

可重复前端检查：在 `web` 执行 `npm test`、`npm run build`。Java 聚焦检查：`mvn -Dtest=CmdbMaintenanceIntegrationTest,AlertIntakeAuthorizationIntegrationTest,OpsPilotApiIntegrationTest,ProblemManagementIntegrationTest,IncidentQueryIntegrationTest test`。MySQL 类沿用已有 `opspilot.scoped.eval.mysql.enabled` 及环境变量开关，由独立临时数据库运行；测试不应指向生产库。

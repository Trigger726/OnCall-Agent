# V1.7 checkpoint-21：OpenTelemetry 异步调查链路

日期：2026-09-17。状态：本地定向、全量回归、前端、JAR 与远端六项 CI 全部通过。V1.7 整体仍在持续迭代。

## 本轮目标

checkpoint-20 已解决执行 JVM 崩溃后的持久化终态收敛，但一次告警从 HTTP 接入、异步 Agent 线程、工具编排到 Prometheus/Loki Provider 仍只能分散查日志和指标。本轮目标是补齐可验证的业务 Trace，同时不将敏感 payload 或高基数查询写入 span。

## 实现与边界

- 引入 `micrometer-tracing-bridge-otel` 与 `opentelemetry-exporter-otlp`，使用 Spring Boot 3.2 原生 `management.tracing` / `management.otlp.tracing` 配置。
- 默认 `OTEL_TRACING_ENABLED=false`，保持 H2 零依赖演示；部署环境显式配置 OTLP/HTTP endpoint 和采样率。
- 仅定义四类业务 span：

| span | 父级 | 关键非敏感标签 |
| --- | --- | --- |
| `opspilot.alert.intake` | HTTP intake span | source、severity、action、alertId、incidentId |
| `opspilot.agent.run` | HTTP investigation span，或无上下文时的根 | runId、incidentId、trigger、status、reportId |
| `opspilot.agent.tool` | agent run | tool、status、evidence count |
| `opspilot.provider.query` | agent tool | kind、providerId、outcome |

- `AgentExecutionManager` 在请求线程提交任务前捕获当前 span，worker 再恢复 scope。测试故意先结束 HTTP 根 span、后启动 worker，仍得到同一 traceId 和正确 parentSpanId。无父 span 时不 scope `null`，任务正常执行，run 可自成新根。
- span 不包含告警标题/描述、labels、PromQL/LogQL、Token、Authorization 或 IP。Provider 异常会标记失败并只记录异常类型，不记录可能包含 URL/查询/凭证的异常 message；不改变原有重试、熔断和本地降级语义。

## 新旧对比与 Demo 保留

| 能力 | checkpoint-20 及更早 | checkpoint-21 |
| --- | --- | --- |
| 告警到调查关联 | 持久化 ID、时间线、审计，需分开查询 | trace 直接关联 Alert/Incident/run ID |
| 异步线程 | 持久化任务和事件，无 trace 父子上下文 | HTTP 父 span 传递到 run/tool/provider |
| Provider 诊断 | 步骤账本和熔断状态 | 追加 provider 子 span 与成败结果 |
| 隐私边界 | 日志证据脱敏 | Trace 额外限制为 ID/状态/类型，不写 payload |

本轮没有更改 UI，因此不用旧页面截图冒充 Trace 证据。checkpoint-14 至 20 的页面、Redis 故障和双 JVM 证据全部保留；`docs/DEMO.md` 只追加了可选 Trace 工程加演。

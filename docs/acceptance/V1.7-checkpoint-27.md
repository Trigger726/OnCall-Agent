# V1.7 checkpoint-27：真实 SLI 分母与服务错误预算

日期：2026-09-21。状态：部分通过。实现、本地全量 H2、前端构建/测试和真实页面已通过；真实 MySQL 与远端 CI 待最终复核。

## 为什么不是给 MTTR 加一条“99.9%”目标线

[Google SRE Workbook](https://sre.google/workbook/implementing-slos/) 建议把 SLI 表达为好事件数除以总事件数，并让工具统一使用 numerator、denominator 和 threshold。Incident 数、MTTA 或 MTTR 没有用户请求分母，不能据此计算可用性错误预算。因此 checkpoint-26 的服务级事故响应视图继续保留，本检查点另建服务 SLO 数据链路。

## 实现与边界

- Flyway V19 为 CMDB 服务保存 SLO 名称、目标百分比、1–90 天滚动窗口、好事件/总事件 PromQL 模板、启用状态、版本和修改人；结算与认证服务各有一条可修改的种子目标。
- `GET /api/v1/slo/objectives` 在指定或当前评估时刻调用 Prometheus instant query。模板中的 `{{service}}` 和 `{{window}}` 由服务端安全替换；表达式可直接使用 counter 的 `increase()`，也可换成生产 recording rule。
- 仅当两条查询各返回唯一数值、总事件大于 0、且 `0 <= 好事件 <= 总事件` 时计算 SLI、允许坏事件数、已消耗与剩余错误预算。多序列、空结果、零分母、矛盾值、Provider 关闭或失败均返回可区分状态，不回退本地演示数据。
- 管理员/运维经理可通过 `PATCH /api/v1/slo/objectives/{id}` 调整目标和窗口；服务端要求查询模板真实使用窗口占位符，采用乐观锁并记录审计。值班员只读。
- 运营分析页将旧有 Incident 响应指标与新 SLO 表分区展示，明确二者分母不同；Prometheus 默认仍关闭，因此默认 Demo 会诚实显示“未启用”。

## 可证伪验收

1. fixture 返回 `9950 / 10000`：SLI 必须为 `99.5%`。认证目标 `99.9%` 时允许 10 个坏事件，实际 50 个，剩余 `-40`、消耗 `500%`，状态为 `BREACHED`。
2. 总事件为 0 时必须为 `NO_DATA`；好事件大于总事件时必须为 `INVALID_DATA`；两种情况均不得返回 SLI。
3. Prometheus 返回多条 series 时协议测试必须失败，不能随意取第一条。
4. ON_CALL 修改返回 403；管理角色带 v0 修改成功变 v1，再用 v0 返回 409；未使用 `{{window}}` 的查询返回 400。
5. Flyway V19 必须同时通过 H2 与真实 MySQL 8.4；完整前后端、Trace、Redis、双 JVM 与容器门禁通过后才能标记为“通过”。

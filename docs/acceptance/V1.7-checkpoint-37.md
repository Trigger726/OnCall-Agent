日期：2026-09-23。状态：部分通过。H2/API、前端测试与构建已通过；真实 MySQL 并发和浏览器渲染尚待远端/实页验证。

## 动机与语义

checkpoint-35/36 的 `DELIVERED` 只证明 webhook 接收端返回 2xx，不能说明行动项负责人已看见或接手。[PagerDuty 的事故状态文档](https://support.pagerduty.com/main/docs/incidents)明确区分 acknowledged 与 resolved；本轮借鉴“确认处理中不等于解决”的语义，但不照搬其自动停止升级策略。复盘行动项的确认独立于通知开关和通知状态：当前负责人登录后对已发布、仍开放的行动项显式确认；完成仍需单独操作，旧的逾期升级事实不会因确认而被关闭。

## 可证伪验收

1. V23 为行动项保存确认人、时间和外键；Owner 之外的管理员/经理不能代替本人确认，AUDITOR 被角色门禁拒绝；草稿和未确认即完成的行动项拒绝补记。
2. 同一负责人重复或并发确认只改变一次版本、写一条时间线和一条审计；确认后仍为 `OPEN`，完成必须带更新后的版本，完成后保留原确认事实。
3. 全局运营表与 Incident 详情分别显示 webhook 回执、负责人确认和完成状态；当前负责人可在两个入口确认，不能由 `DELIVERED` 自动推导确认。
4. H2、MySQL 8.4 V1–V23、全量后端、前端测试/构建及旧 CI 门禁通过；页面实测与移动布局单独记录，不以构建替代。

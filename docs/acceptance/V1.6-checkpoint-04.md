## 2. 本次修正的问题

checkpoint 03 把每条批准判断晋级为一条评测 case。旧评测器又按“一条 case 等于一个查询”计算指标，因此同一查询若有两个相关 Runbook，会被执行和计权两次；0–3 级判断进入评测后也只剩“是否相关”，等级信息没有参与排序质量计算。

本检查点将数据解释修正为：

```text
query
  -> stableKey A, grade 3
  -> stableKey B, grade 2
  -> one evaluation query + two qrels
  -> Recall@3 / MRR / NDCG@3 / citation hit
```

这不是新增一个装饰性指标，而是修正评测样本单位和相关性等级丢失两个实质问题。

## 4. 实现说明

### 4.1 Flyway V10

`V10__graded_runbook_relevance_evaluation.sql`：

- 给 `runbook_retrieval_eval_case` 增加非空 `relevance_grade`，旧种子默认 3，V9 人工 case 从原 judgment 回填。
- 用检查约束保证进入正相关评测集的等级只能是 1–3；等级 0 仍只作为负样本事实保留。
- 给评测 run 增加 `judgment_count`、`baseline_ndcg_at_3` 和 `ndcg_at_3`；新列允许为空以兼容已经存在的历史 run。

### 4.2 查询与 qrels 聚合

评测器先按查询原文聚合，再按 Runbook `stableKey` 聚合。每个唯一查询只执行一次检索：

- `caseCount`：唯一查询数。
- `judgmentCount`：不同 query-document qrels 数。
- 同一 query-document 若出现多次批准判断，相关性等级取算术平均。
- 数据集版本哈希包含聚合后的查询、文档、等级和当前已发布 Runbook 版本，因此等级变化会生成新版本。

### 4.3 指标定义

- Recall@3：对每个查询计算前三名召回的相关文档数 / 该查询全部相关文档数，再对查询取平均。
- MRR：每个查询只取首个相关文档的倒数排名。
- NDCG@3：`DCG = Σ((2^grade-1)/log2(rank+1))`，再除以相同 qrels 的理想 DCG。
- 首位稳定引用命中率：第一名是任一相关文档且引用带匹配 stableKey 时记为命中。

NDCG 的选择与 [OpenSearch 搜索质量评估](https://docs.opensearch.org/latest/search-plugins/search-relevance/evaluate-search-quality/) 及 [Elasticsearch ranking evaluation](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/search-rank-eval) 对分级相关性和归一化 DCG 的定义一致。它补足了 Recall 只看“是否召回”、MRR 只看“第一个相关结果”的盲区。

# V1.7 双主题 UI 可重复验收

2026-10-11：将上一轮临时浏览器检查固化为仓库脚本。本轮仅测试/说明/证据，不修改封版业务、Vue、CSS、生成资源或 CI，不再自动扩项。

## 运行入口

前提：Node.js、Java 21、`scripts/browser` 已安装的锁定 Playwright 1.63，以及 Chrome。不自动安装依赖，不重建或覆盖任何 JAR。

在仓库根目录执行：

```powershell
$env:JAVA_HOME = 'C:/Program Files/Java/jdk-21'
node scripts/verify-ui-packaged.cjs --jar target/opspilot-v1.7-ui-claude.jar
node --test scripts/browser/tests/*.test.cjs
```

也可在 `scripts/browser` 运行 `npm run verify:ui -- --jar target/opspilot-v1.7-ui-claude.jar`；JAR 路径始终相对仓库根目录解析。省略 `--jar` 时读取既有 `target/opspilot-0.1.0-SNAPSHOT.jar`，不会打包。仓库位置无需硬编码。Chrome 不在默认安装位置时设置 `OPSPILOT_BROWSER_EXECUTABLE`；其他平台需已有可用 Chromium，未做本轮跨平台实机验证。

脚本固定使用 loopback 和新临时 H2，覆盖数据库驱动/账号、关闭 AI、通知、轮转、恢复、Redis outbox、自动重放及遥测。9913/9914 已占用则失败，不停止占用者；可用 `OPSPILOT_UI_QA_PORT` 指定另一个端口及下一管理端口。浏览器入口要求独立 runner 标记，防止默认连到常用 Demo 端口；标记不是安全边界，不应手工绕过后连接已有数据库。

健康检查要求真实 `UP`，启动等待约 60 秒（单请求最长 5 秒），浏览器等待最多 180 秒。成功后认证关闭所属 JVM，验证端口释放与原 JAR 摘要不变；失败返回非零并保留临时诊断，不误报通过。所有截图、日志和数据库默认留在系统临时目录，路径打印在输出中。

## 本轮实际验收

目标流程：登录页键盘切换 → 浅色偏好跨刷新/路由保留 → 桌面及手机业务页 → 退出清除认证但保留主题。对原精修效果的对照仍见[上轮截图与记录](V1.7-ui-claude-design.md#截图)，本轮没有视觉改动。

环境：Windows、Java 21、现有 Playwright + Chrome，`http://127.0.0.1:9913`，1440×1000、390×844，额外检查 320×740。Browser 插件不可用，因此使用已有 Playwright，无新增依赖。

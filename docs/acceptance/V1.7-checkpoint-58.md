## 本轮发现与改动

真实 HTTP 控制器测试复现了可配置周期与固定 30 天阈值的失配：28 天应快速告警却返回慢速告警，90 天过早返回快速告警。首轮 11 项中 6 项失败，完整日志保留在 target/cp58-period-first-failure.log。按 [Google SRE 的预算消耗公式](https://sre.google/workbook/alerting-on-slos/)计算阈值：周期小时数 × 预算消耗比例 ÷ 长窗口小时数。30 天仍为 14.4/6/1；28 天为 13.44/5.6/0.933333…。1、2 天目标的票据长窗口限制在目标周期，短窗口为长窗口的 1/12（1d/2h、2d/4h）。界面查询和导出规则复用同一策略。

另一个首失败：正分数事件 0.000001/0.00001 在计算前被四位小数舍成 0/0，结果错误返回 HEALTHY（target/cp58-fractional-first-failure.log）。有效样本现保留原始精度到判定，展示燃烧率仍按既有格式取四位小数。测试用极小正数验证算术边界，不据此宣称低流量告警策略已满足生产需求。

新增只读接口 GET /api/v1/slo/objectives/{id}/versions/{version}/prometheus-rules：当前活跃管理角色可导出捕获版本；旧版本409、停用409、不存在404、非法版本400。读取使用一致事务快照，不查询外部 Provider，不自动部署规则、不写业务状态。规则有目标/版本/服务标签、固定策略版本和内容 SHA256；以 YAML 兼容 JSON 编码转义所有动态字符串并统一 LF。默认30天目标为15条记录规则、3档优先级燃烧率告警和5条数据不可用告警，共23条；1/2天所需6个不同窗口对应27条。

规则拒绝无分母、多系列、矛盾计数、负数、NaN/Inf及超过60秒的记录；快档优先于慢档，票据排除已触发的快/慢档。每30秒评估一次。数据缺失有独立告警，不能当作健康；燃烧率告警 resolved 也不能自动关闭 Incident。

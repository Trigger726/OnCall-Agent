## 问题与实现

- 原 GET 只有计划过滤和最新200条上限。页面若在返回后筛选本人/状态，较旧待办会被较新无关请求挤出。
- 新增 `scope=ALL|MINE`（缺省 ALL，保持旧调用）及可选 `status=PENDING|ACCEPTED|REJECTED|WITHDRAWN`。全部状态须省略 status；非法范围/状态返回400 `ONCALL_HANDOFF_INVALID`，不悄悄扩大查询。
- MINE 从认证主体取本人ID，匹配申请人或指定接班人，不接受调用方身份替代。ALL 仍为所有登录角色可读，AUDITOR无新增写权限。
- 计划、本人、状态在同一 SQL WHERE 中先过滤，再倒序取201行；返回最多200与对应筛选结果的truncated。数据库时间、原时段/版本/幂等/事务规则不变。
- PENDING 包含时段已结束但未作决定的请求，不虚构 EXPIRED 持久化状态；接受仍受既有数据库时钟门禁保护。

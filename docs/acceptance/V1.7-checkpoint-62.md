# OpsPilot V1.7 检查点62：默认消费者与饱和反馈

## 阶段一：新增真实故障门禁（2026-10-02，待验）

上一轮61已经证明单消费者持久队列可跨SIGKILL和不同容器重建恢复，但没有证明默认十消费者的在途数据。当前工作树先保持生产队列/重试策略及历史单消费者实验，新增只暴露指标、完全不覆盖exporter的配置，再用相同真实调查/原Trace/六工具/两跨JVM分支验证。

已核对最新文档提交 `29ce85aae03dcab49091be8e338dd70e906ab2e7` 的 [Run37000163284](https://github.com/Trigger726/OnCall-Agent/actions/runs/37000163284) 十三作业completed/success；本机Docker daemon仍不可用，Compose静态校验不替代Linux实验。

默认消费者实验会逐个发送独立已知ID探针，实际观察十个在途导出请求后再生成调查；重建后探针也须全部查回，不能只剩队列积压图就通过。指标是 aggregate，在途计数不能冒充每个探针的单条持久ACK。旧Demo、61首失败、历史JAR与未提交改动保持。

队满实验/可选Prometheus反馈仍待实现和实测。目标是直接对照OTLP接收、入队拒绝计数和最终缺失的已知Trace，而非承诺健康UP等于送达；单消费者/小队列/短批次是故障测试专用参数，不改生产容量。

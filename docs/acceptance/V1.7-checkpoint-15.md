# V1.7 checkpoint-15：真实双 JVM Agent 事件链路

日期：2026-09-12。状态：测试实现已编译，真实环境待验。

## 目标与实现

新增独立条件测试 `DistributedAgentEventsIntegrationTest`：Testcontainers 启动 MySQL 8.4 与 Redis 7.4；两个独立 Java 子进程启动 OpsPilot Web 服务，使用不同 PID、端口、Spring 上下文、数据库连接池和 Redis 接收游标，共享同一数据库与 Stream。不是同一 JVM 内两个对象的替代测试。

A 通过真实登录/POST 接口发起调查，关闭发起 POST 的连接；A 的测试专用只读工具在文件闸门等待。A、B 分别通过带认证的 GET SSE 订阅，确认两端收到闸门步骤开始后才放行调查。只有测试工具的同步使用本地文件，事件传输必须经过生产 outbox/Redis/数据库/SSE 路径。

两个实例都将定期 catch-up 间隔与首次延迟设为一小时，真实用例在该时间窗内结束。关闭该兜底干扰后，后续终态必须由自动 relay/receiver 唤醒订阅；测试不手动调用 poll、relay 或 catchUp。生产默认首次延迟仍为 0，默认补读间隔仍为 5 秒。

断言两实例 PID 不同，A、B 从 0 读取的事件 ID 列表都与 B 的数据库回放接口完全一致、无重复且以 RUN_COMPLETED 结束。随后在 B 使用中间游标重连，验证只返回余下事件直到终态。测试工具仅在 src/test 中，不打入生产 JAR。

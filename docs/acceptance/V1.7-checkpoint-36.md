# V1.7 checkpoint-36：独立进程通知接收与重试联调

日期：2026-09-23。状态：待远端容器验收。本地已完成脚本语法、Node 语法、Compose 合并配置及 `git diff --check`；本机 Docker daemon 不可用，不把静态检查算作投递成功。

## 本轮变化

保留 checkpoint-35 的默认关闭通知 outbox 及全部旧 Demo。本轮新增隔离 Compose 验收夹具：Node 接收器运行在与 OpsPilot 不同的容器/进程中，共享网络命名空间，以 `127.0.0.1` HTTP 满足现有“生产 HTTPS、本机 HTTP”限制；没有为测试放宽生产 URL 校验。接收器首个稳定幂等键请求返回 503，第二次返回 204，只在诊断记录中保存鉴权是否正确，不保存 Bearer token。脚本使用独立 project/volume 与运行时随机 token，创建一条已逾期行动项，走真实管理员 HTTP 扫描，然后核对 MySQL 通知行、两次接收、重试回执和重复扫描零新增。

## 可证伪验收

1. Flyway 初始化的真实 MySQL 中生成一条通知；独立 Node 进程收到的两次请求分别返回 503/204，均具备正确 Bearer 鉴权、相同 `Idempotency-Key` 与冻结业务载荷。
2. 通知最终为 `DELIVERED:2:204`；再次扫描不产生升级或通知，也不增加接收次数。
3. 远端新增 CI job 运行该脚本，保留不含 token/JWT 的接收记录、数据库摘要和容器日志；原有十项门禁仍通过。

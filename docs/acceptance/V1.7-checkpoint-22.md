# V1.7 checkpoint-22：Collector、Tempo 与 Grafana Trace 闭环

日期：2026-09-18。状态：实现与本地静态检查完成；本机 Docker daemon 不可用，远端真实容器门禁待提交后回填。V1.7 整体仍在持续迭代。

## 本轮目标

checkpoint-21 已证明应用能生成正确的 OpenTelemetry 父子 span，但证据止于进程内 SDK exporter。本轮补齐开发/验收环境里的完整管线：应用通过 Collector 写入 Tempo，再由 TraceQL 与 Grafana 数据源读回；同时验证存储后的层级和隐私边界。

## 实现

- `docker compose --profile tracing` 增加固定版本组件：OpenTelemetry Collector Contrib `0.158.0`、Tempo `2.10.8`、Grafana `13.2.2`。
- 默认 `docker compose up` 仍关闭 Trace 且不启动三项额外服务；受控演示显式启用 profile 和 `1.0` 采样率。
- Collector 接收 OTLP/HTTP 与 OTLP/gRPC，使用 memory limiter、batch、有界发送队列和失败退避，再通过 OTLP/gRPC 写入 Tempo。
- Tempo 使用 24 小时本地存储，定位为开发/验收后端；Grafana 匿名只读并预置 Tempo、Prometheus 数据源。
- `scripts/verify-tracing-pipeline.sh` 使用独立 Compose project/volume，避免清理日常 MySQL 数据；退出时收集日志并销毁自己的容器与卷。

## 自动化契约

独立 CI job 将：

1. 启动 MySQL、OpsPilot、Collector、Tempo、Grafana。
2. 提交带动态隐私哨兵的真实告警，再登录并对新 Incident 执行六工具调查。
3. 用 TraceQL 按动态 run ID 搜索 trace，并通过 Tempo API 与 Grafana datasource proxy 两条路径读回。
4. 断言调查状态 `COMPLETED`、1 个 `agent.run`、6 个 `agent.tool`、2 个 `provider.query`，tool 的 parent 是 run，provider 的 parent 属于 tool。
5. 在完整 Tempo trace JSON 中搜索动态哨兵，发现告警标题、描述或 label 泄漏即失败。
6. 上传搜索结果、完整 trace、扁平 span、Grafana 数据源健康和 Compose 日志作为 Actions artifact。

本地已完成：

- `docker compose --profile tracing config --quiet`：通过。
- `bash -n scripts/verify-tracing-pipeline.sh`：通过。
- `git diff --check`：通过。
- `docker version`：明确失败，原因是本机 Docker Desktop Linux engine 未运行；因此不将静态检查描述成容器通过。

## 当前不声明的能力

- 本报告在远端 job 成功前不声明真实容器链路通过。
- 24 小时本地盘不是生产高可用 Tempo；尚未验证对象存储、容量规划和长期保留。
- Collector 配置了队列与退避，不等于已验证 Collector/Tempo 故障期间零丢失；故障注入仍待单独门禁。
- 尚未覆盖两个真实服务之间的 W3C `traceparent` 传播、TLS/鉴权、多租户和生产采样成本。
- Grafana datasource proxy 可自动化证明查询路径，但真实页面截图需在可运行 Docker 的浏览器环境单独归档，不能用静态配置冒充。

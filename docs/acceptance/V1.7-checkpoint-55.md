# OpsPilot V1.7 检查点55：真实检索复核质量趋势

## 当前结论

2026-09-28：本地限定通过。后端定向5项、前端50项、双时区全量回归、生产构建和八脚本真实浏览器通过；MySQL与远端CI待验。不是整体目标完成，也不是生产命中率验证。

目标：让管理角色按实际持久化检索查询的发生日，观察结果返回与独立复核质量，和原有固定集离线评测分开。参考 [Elastic 排名评测文档](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/search-rank-eval) 对人工评分及未评分文档的显式区分；本实现选择更严格的非空查询全量复核门槛，不宣称复刻其默认公式。

## 统计口径

| 指标 | 分子 / 分母 | 未知处理 |
| --- | --- | --- |
| 持久化查询 | 查询事实行数；同文本多次搜索仍是多次请求 | 记录失败的请求不在库中，不能称总请求量 |
| 结果返回率 | 非空查询 / 结果数已知查询 | 历史清理或损坏无法恢复的结果数排除并计数 |
| 非空全量复核覆盖 | 全部去重返回文档均已批准独立复核的查询 / 非空查询 | 部分复核、待审、拒绝、无复核均不能冒充完成 |
| 可计分子集 Hit@K | 全量复核且至少一个复核等级≥2的查询 /（全量复核非空查询 + 已知空结果查询） | 部分复核即使有正相关也不计分，零分母为null/N/A |

固定实际执行引擎（BM25_LOCAL_V1或HYBRID_RRF_V1）与K，来源可选CONSOLE/AGENT/ALL；不按请求AUTO/HYBRID冒充实际执行引擎。默认30天，最大90天，按数据库本地日期、半开时间范围查询，补无流量日但不补评分。归属查询日，复核为读取时现状，晚复核会改变以前日期的质量值；不是当日评分历史快照。仍存在人工选择、混合角色/查询难度和小样本偏差，不能从子集率外推全量质量或宣称版本改善。

K沿用现有检索协议，是返回片段上限，可能包含同一文档多个片段；复核按文档去重。因此此处为返回K片段内相关文档的查询命中比例，不冒充去重文档Top-K排序质量、Recall或NDCG。

## 持久化与保留期

- V29 Java Flyway迁移新增returned_document_count，为稳定文档键去重数，不是片段数；新检索和原快照同一INSERT。
- 旧ACTIVE快照只恢复可解析且结构完整的计数，500行keyset分批，原文不改写；旧PURGED或损坏数据保留NULL，旧清理留下的[]不当作真实空结果。
- 新清理继续擦除查询正文/结果/身份，保留非敏感计数与原独立复核事实，因此完整已复核查询的趋势不随保留期错误归零。
- 查询先按时间/来源/引擎/K过滤，再按search_id聚合复核，最后逐日聚合，避免多返回项连接膨胀查询分母。管理角色只读API不返回查询正文、结果摘录或身份。

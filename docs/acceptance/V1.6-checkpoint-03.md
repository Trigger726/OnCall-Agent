## 3. 实现说明

### 3.1 Flyway V9

`V9__runbook_relevance_feedback.sql` 新增：

- `runbook_retrieval_query`：保存不可变检索快照和 `query_hash`，区分 `CONSOLE / AGENT` 来源。
- `runbook_relevance_judgment`：保存 query-document 等级、提交人、复核状态、复核人和乐观锁版本。
- `runbook_retrieval_eval_case.source_type / judgment_id / reviewed_by`：区分 `SEED` 与 `HUMAN_JUDGMENT`，并保证一个判断最多晋级一次。

控制台与 Agent 走 tracked 入口；评测走内部 untracked 入口。快照持久化采用 best-effort：遥测故障不阻断 Runbook 检索，响应中没有 `searchId` 时页面禁用反馈。

### 3.2 判断与复核状态

```text
real search -> immutable snapshot -> PENDING judgment
                                      | independent APPROVE + grade >= 2
                                      +-------------------------------> HUMAN_JUDGMENT eval case
                                      | independent APPROVE + grade < 2
                                      +-------------------------------> negative fact only
                                      \ REJECT ------------------------> rejected fact only
```

- 判断唯一键为 `searchId + documentStableKey + judgedBy`。
- 待复核阶段重复提交会更新等级并递增版本；已复核判断不可修改。
- 复核角色只允许 `ADMIN/OPS_MANAGER`，服务端再检查不能自审。
- 正样本晋级与复核处于同一事务；评测数据集版本由 case 内容和已发布文档版本共同计算。

### 3.3 成熟项目对照

- [OpenSearch Judgments](https://docs.opensearch.org/latest/search-plugins/search-relevance/judgments/) 将判断定义为特定查询上下文中的文档相关性等级，并区分显式人工判断和隐式行为判断。
- [OpenSearch Query Sets](https://docs.opensearch.org/latest/search-plugins/search-relevance/query-sets/) 支持从真实用户查询采样或导入查询集。
- [OpenSearch Search Relevance Workbench](https://docs.opensearch.org/latest/search-plugins/search-relevance/using-search-relevance-workbench/) 将 query set、search configuration、judgment list 和 experiment 分开管理。

OpsPilot 本检查点实现的是适合当前规模的显式人工最小闭环，没有把点击直接当相关，也没有用 LLM 自动批准自身判断。

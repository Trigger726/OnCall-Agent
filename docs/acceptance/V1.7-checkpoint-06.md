# OpsPilot V1.7 验收报告：检查点 06

## 问题与复现

2026-09-07 自检发现：排队调查取消时，Future 被取消但仍留在有界执行队列中。一个 worker 被运行中任务占用、队列容量为 1 时，取消排队任务后提交替代任务仍抛出 `TaskRejectedException`，导致用户已取消调查却不能恢复接单容量。

扩展 `AgentExecutionManagerTest` 的队列饱和用例：保持运行任务阻塞，取消队列中的任务，然后提交替代任务；释放 worker 后要求替代任务执行且已取消任务不执行。修复前该断言直接失败，拒绝信息为 active threads = 1、queued tasks = 1。

## 修复与边界

取消 Future 后从底层线程池移除对应队列项；提交完成后再检查取消状态，补偿取消发生在入队之前的交错。当前执行器未配置 TaskDecorator，队列项就是所提交的 Future。运行中任务仍通过中断取消，队列容量和拒绝策略保持原配置。

## 验证

`mvnw -B -Dtest=AgentExecutionManagerTest,AgentRunCancellationIntegrationTest test`：3 项通过、0 失败、0 错误、0 跳过。远端全量门禁结果随后补充。此改动不涉及数据库迁移或页面结构。

## Demo 对比

保留 V1.5 取消与队列饱和演示。新增工程对照：单 worker 持续处理 A，B 排队；取消 B 后立即提交 C。旧版 C 被拒绝；新版 C 入队，待 A 释放后执行。测试以闸门保持 A 阻塞，避免把 worker 恰好腾空误认为容量已主动回收。

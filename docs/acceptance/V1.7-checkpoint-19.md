# V1.7 checkpoint-19：移动端调查上下文与取消终态恢复

实施与远端复核日期：2026-09-16。状态：实现、13 项前端测试、生产构建、真实浏览器新旧对照及六项远端 CI 门禁通过。

## 用户可见变化

OnCall 助手在手机和平板宽度新增“打开调查上下文”入口。右侧抽屉复用桌面端同一份 Incident 上下文、证据快照、继续追问和 Agent 调查组件，不复制业务状态。抽屉支持显式关闭和遮罩关闭；会话切换会关闭旧抽屉，避免标题与内容属于不同会话。桌面大于 1180px 继续使用原有内联上下文栏。

按钮补充 `aria-label`、`aria-expanded` 和 `aria-controls`，关闭按钮可被辅助技术识别。当前没有实现键盘焦点陷阱和 Escape 关闭，因此本检查点只声明入口和基础语义可达，不声明完整 WCAG 对话框合规。

## 严格回归发现并修复的取消缺陷

首次严格测试中，取消 API 已将服务端 run 持久化为 `CANCELLED`，事件表也有 `RUN_CANCEL_REQUESTED / STEP_CANCELLED / RUN_CANCELLED`，但原始 POST SSE 仍停在 `STREAMING`。原因边界是取消会中断拥有原始 POST 响应的执行线程，该响应可能在终态 frame 刷出前失效；不能把“数据库已取消”等同于“页面已观察到取消”。

Incident 工作台与 OnCall 助手现在在取消 API 成功后主动中止旧 POST 连接，并对同一 run 建立 GET-only 持久化事件订阅。它从数据库回放终态，不创建第二个调查，不更换 run 编号，也不依赖手工刷新。取消按钮增加控制中状态，避免重复点击。此修复沿用 checkpoint-18 的有界重试、游标去重、事件归属校验和终态停止语义。

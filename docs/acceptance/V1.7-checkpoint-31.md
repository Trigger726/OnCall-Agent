# V1.7 checkpoint-31：拒绝项自动重放与载荷保留期

日期：2026-09-23。状态：通过。本地 H2/前端/JAR/真实 HTTP 与响应式页面、MySQL 8.4 和远端七项 CI 均已通过。

## 目标与边界

checkpoint-30 已有脱敏拒绝台账和人工受控重放，但待补录 CMDB 的坏项仍依赖值班人反复刷新与点击，脱敏快照也没有保留期。本轮只对 `RESOURCE_NOT_FOUND` 开启可选的自动重放：默认关闭，按到期时间和批量上限选取；每次以数据库条件更新领取 token 租约，失败后采用有上限的指数退避加抖动，超过次数停下并保留人工重放入口。其他参数/映射错误不自动重放，需上游修复后重新投递或人工处理。该取舍遵循 [AWS 重试与抖动建议](https://docs.aws.amazon.com/wellarchitected/2023-04-10/framework/rel_mitigate_interaction_failure_limit_retries.html)，也避免把永久配置错误当瞬时故障无限重试。

载荷默认保留三天，到期后按批清理 payload 和可能含业务信息的摘要字段，仅留拒绝码、状态、计数、解决关联与审计事实。租约有效期间不清理；清理后手动重放返回 410，新的原始投递可在同一稳定拒绝键下恢复可重放快照。保留期是演示默认值，生产需按组织数据策略设置；具体字段清理原则参考 [OWASP 日志指南](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html)。

## 可证伪验收

1. 重复坏投递不得重置 `auto_replay_count`、重放截止或租约；后续投递出现不同错误时，台账保留首份快照对应的错误；到达上限后不再自动领取。
2. CMDB 未补录时，自动重放只更新一次失败事实并安排有界下一次；补录后下一次成功，只生成一条 Alert。
3. 自动预算耗尽不阻止权限受控的手动重放。
4. 到期的非租约载荷清理为 `PURGED`；有效租约保护载荷；清理后手动重放明确 410，重新投递可恢复快照。
5. 页面区分待处理、自动排程/耗尽、已清理，并隐藏已清理项的重放按钮。

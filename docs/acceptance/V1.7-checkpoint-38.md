# V1.7 checkpoint-38：待接手行动项运营筛选与通知时间精度

日期：2026-09-25。状态：通过（限本检查点）；本地 H2/API、前端构建、打包页面、桌面/390px 浏览器交互及远端 MySQL/11 项 CI 均已通过。

## 问题与语义

checkpoint-37 已能由负责人本人确认接手，但运营表只能逐行查看，无法直接筛出未确认项，也没有待接手总量。新增 `openUnacknowledged`，只计已发布复盘下 `OPEN` 且 `acknowledged_at IS NULL` 的行动项；草稿尚不能接手，不进入运营摘要或全局列表，仍可在 Incident 详情编辑。这个摘要是全局当前快照，不受上方按 Incident 创建日期筛选的响应指标窗口影响。列表新增 `ALL / ACKNOWLEDGED / UNACKNOWLEDGED` 筛选，按持久化确认时间判断，可与本人范围、完成状态、仅逾期组合；它不推断 webhook 端点回执或负责人实际阅读情况。历史上未确认但已完成的行动项仍可被“未确认”筛出，需结合“开放”状态聚焦待接手任务。

首次全量回归还暴露通知入队后的极短时间边界：入队时间使用纳秒值，H2 的微秒存储可能向上舍入，而派发器按截断到微秒的 `now` 查找；同一微秒立即派发偶发返回 0。失败时观测到 `next_attempt_at=22:47:33.238941`、当前 UTC `22:47:33.238940600`。入队时同样截断到微秒，保持与派发器一致，不靠测试延时掩盖。

参考[Grafana IRM官方数据保留](https://grafana.com/docs/grafana-cloud/observe-and-act/respond-to-incidents/reference/data-retention/)：通知/投递与Incident使用不同保留策略。本项目选择只清理冻结payload，不删除换班、通知元数据、技术回执或审计；并非完整个人信息删除或复刻商业产品策略。原OnCall基线0cd654ea49957d05c0e5c683c0e945a5a87c5bab与86/87历史Demo继续保留。

- 清理独立开关默认false，期限默认30日，可配置1–3650日；新事件同业务事务冻结数据库会话时间期限，重试/改配置不能延长。既有V35事件迁移期限为其created_at+30日，启用前须审阅历史。
- 开关关闭不删除载荷；已经清理不可通过关闭开关恢复或空载荷外投。每次最多原batch-size项、按期限/id扫描，用数据库时间及条件UPDATE，不使用进程本地时钟。
- 有效CLAIMED租约暂缓清理；到期非在途PENDING/FAILED转SKIPPED/RETENTION_EXPIRED，DELIVERED/SKIPPED保留原技术终态。擦除冻结payload、记录payload_erased_at，保留原投递键/重试指纹/元数据，未从事故事实清表。
- 开关启用后过期事件不得新claim或新人工重试，即使清理批次尚未覆盖；同原版本/说明的已提交重试回执仍可确认，不重入队/不新增审计。已经发起的外部HTTP不能远端撤回；仅数据库旧lease回执围栏，不声称远端exactly-once/精确物理删除期限。
- 清理可在通知发送关闭时运行，使用同一个独立无排队worker，不占共享调度线程；网络等待与批次互相有界，不新增共享线程积压。

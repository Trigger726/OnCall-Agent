# V1.7 checkpoint-43：有效班次维护与可审计取消

日期：2026-09-27。状态：本地通过；双时区 H2、前端构建、最新 JAR 的真实 HTTP 与桌面/390px 浏览器复验通过，真实 MySQL/远端门禁待补证。

## 业务问题与实现

checkpoint 42 已让到期策略真实执行，但默认班次是 2026-08 历史数据，无法从控制台安排有效值班人。只展示 `NO_TARGET` 而没有维护入口不能闭合运营链路。本轮在原班次卡片、策略和执行记录之间增加班次维护，不替换原始 Demo，也不自动改写历史日期。

参考 [Grafana IRM 临时覆盖](https://grafana.com/docs/grafana-cloud/observe-and-act/respond-to-incidents/on-call-schedules/shift-swaps-overrides/) 的明确替班与保留原计划思路；本项目只实现单次普通班次/临时覆盖、查询和取消，不复制其轮转、优先级多层、换班请求和日历同步能力。

- V25 为班次增加版本、说明、取消时间与原因；历史行原样保留，取消不是 DELETE。
- ADMIN/OPS_MANAGER 创建/取消，ON_CALL/AUDITOR 只读；负责人须活跃并具有 ADMIN/OPS_MANAGER/ON_CALL 职责。
- 排班按现有数据库会话时间输入与展示，不按浏览器时区自动转换；响应带数据库当前时间与建议时段。时间须为整秒，结束晚于开始与数据库现在，单班最长 31 天，避免 H2/MySQL 精度与已结束班次歧义。
- 写操作先锁同一计划行；同类未取消班次不可重叠，区间为 `[开始, 结束)`，相邻可交接；普通与覆盖可重叠。重叠检查用锁定读，避免 MySQL REPEATABLE READ 的旧快照放行并发冲突。
- 取消需版本和原因；旧版本/重复取消返回 409 且不重复审计。当前值班与升级路由都排除取消班次；撤销覆盖后恢复普通班次，不重写已有升级事件或重新尝试旧 `NO_TARGET`。
- 查询窗口最多 31 天，最多返回 200 条并显式提示截断；包含取消历史，不把“时段内”冒充最终胜出值班人。

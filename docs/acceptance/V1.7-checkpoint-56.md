## 风险与交付边界

检查点55代码的 Markdown/PDF 导入直接发布新版本，控制台和 Agent 随即可检索。此次改为不可变候选：`PENDING_REVIEW -> PUBLISHED / REJECTED / WITHDRAWN`。已有发布手册保留为可信历史，不倒灌为待审。

另一当前有效管理账号才可批准/拒绝；本人只能撤回。批准时将旧发布版置为 SUPERSEDED，提交时捕获的发布基线必须仍匹配，禁止旧候选覆盖后来批准的新内容。正文、元数据、来源、ACL及提交人共同识别相同待审候选，不再仅凭正文哈希复用权限不同的内容。

审核决定绑定候选ID、申请版本、UUID、实际操作者、决定及原始说明哈希；精确重放不重复审计，不复活被替换版本。同键不同内容/跨候选拒绝。说明入库前脱敏，审计不保存正文或原始说明。逻辑手册行锁与候选行锁串行化发布；发布、替换、审核事实和审计在同一事务内。

新页面提供候选台账、正文/ACL/基线核对、批准/拒绝/本人撤回；提交前按账号在 sessionStorage 冻结意图。网络结果未知只能手动同键重试，刷新不会POST；400/403/404/409锁定意图，不自动换版本或改键重提。存储为当前浏览器会话，不宣称跨设备恢复。待审内容不进入普通版本历史、BM25、Agent或已发布向量集合。

这只是知识发布治理，不是执行生产变更的自动化平台。独立批准不证明手册事实正确或消除提示注入风险。

成熟项目参考：[Backstage TechDocs 创建与发布](https://backstage.io/docs/features/techdocs/creating-and-publishing/)采用文档靠近代码、提交/PR/合并后更新的流程。这里借鉴“候选内容与发布内容分离”的工程思路；OpsPilot实现的是数据库内独立复核，不声称接入了Backstage或Git PR审批，也不把参考项目当本项目的测试证据。

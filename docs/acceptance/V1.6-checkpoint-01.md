# V1.6 检查点 01：版本化 Runbook、BM25 与检索评测

日期：2026-09-01

结论：部分通过。Runbook 知识库、角色过滤检索、Agent 复用、固定集新旧对照、H2 自动化和桌面/移动端实页验收已闭环；真实 MySQL 8.4 的 Flyway V7 复验被本机 Docker Desktop 启动故障阻塞，因此本检查点不标记最终通过。

## 本轮交付

- 新增 Flyway V7：`runbook_document` 不可变版本、`runbook_document_acl`、`runbook_chunk`、固定评测 case/run；3 条 V1 内置手册平滑迁移为 v1，并保留原 `runbook` 表作为历史基线。
- Markdown 粘贴和 `.md/.markdown/.pdf` 文件导入；限制 5 MB、PDF 200 页，拒绝加密/不可解析 PDF 和不支持扩展名。相同内容哈希幂等复用，变化内容生成新版本并保留 `SUPERSEDED` 历史。
- 本地 `BM25_LOCAL_V1`：ASCII 词元、中文单字/二元组、标题加权、稳定排序；先按登录角色 ACL 过滤，再生成 `runbook:{stableKey}:v{version}#chunk-{index}` 引用。
- Agent `runbook_retrieval` 工具改为复用同一检索服务和当前操作者角色，不再自行遍历旧表做字符串包含。
- 固定集同时运行 `LEGACY_CONTAINS_V1` 和 BM25；保存数据集版本、Recall@3、MRR、新版首位稳定引用命中率与失败样例。
- 重做“处置手册”页：后端检索、分数/引用、文档来源/版本/ACL、新旧评测对照和管理员导入弹窗；保留历史 demo 的 3 条手册并明确对照。

## 真实 MySQL 待验项

`MySqlCompatibilityIntegrationTest` 已更新为断言 Flyway V7、3 份迁移文档、BM25 引用及 Agent 步骤引用。尝试启动 Docker Desktop 时，宿主机在引擎启动前报错：Inference manager 无法清理 `%LOCALAPPDATA%/Docker/run/dockerInference` 陈旧套接字。未删除 Docker 数据，临时设置已恢复，失败进程已停止。

因此当前证据边界是：V1.5 的 V1-V6 真实 MySQL 曾通过；本轮 V7 只在 H2 MySQL 模式通过，不能据此宣称 V7 已通过真实 MySQL。待宿主机 Docker 恢复后执行：

```powershell
.\mvnw.cmd -B "-Dopspilot.mysql.it.enabled=true" "-Dtest=MySqlCompatibilityIntegrationTest" test
```

## 已知边界与下一步

- 检索为单机内存 BM25，每次按当前可见语料计算，不适合大规模文档；尚未接 OpenSearch、向量召回或重排。
- PDF 仅支持可提取文本，不做 OCR；导入后直接发布，尚无草稿/复核工作流。
- ACL 仅做到系统角色，未细化到部门、资源 owner 或租户。
- 固定集只有 3 条种子样例。下一检查点先扩充标注集，再以相同门禁评估向量召回/重排，而不是预设它一定优于 BM25。

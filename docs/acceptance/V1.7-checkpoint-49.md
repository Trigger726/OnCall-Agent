# OpsPilot V1.7 检查点 49：定向接班请求后端

## 状态与范围

2026-09-27：部分通过（后端阶段已验，接班UI仍待交付）。后端/真实HTTP与原有界面回归、真实MySQL50项和修复后十二项CI全绿已直接验证。上一检查点的历史 Demo、截图和原始 OnCall 归档不变。本检查点先交付服务端事务与权限，不把 API 实现等同于完整换班产品；接班页面、桌面/移动新旧对照和接班浏览器门禁仍待后续闭环。

参考 [Grafana IRM 请求式接班](https://grafana.com/docs/grafana-cloud/observe-and-act/respond-to-incidents/on-call-schedules/shift-swaps-overrides/manage-swaps/) 的“提出覆盖请求、本人接受后承担责任、保留原轮转”业务模型。OpsPilot 本阶段为指定接班人，不支持开放认领、双向互换、外部提醒或日历同步；允许正在进行中的原班次申请，但接受只作用于剩余时间。

## 已实现并通过本地验证

- V27 新增接班请求表，外键关联原班次、计划、双方、决策人与新覆盖；申请人 + UUID 请求键唯一，新覆盖 ID 唯一，不改写历史迁移。
- 本人申请自己的普通班次；指定接班人接受/拒绝，申请人撤回，管理角色无权替他人同意。AUDITOR 只读。
- 创建幂等键必须匹配不可变申请内容；终态决策重试须匹配原版本与说明，零重复写入，不复活已取消覆盖。
- 决策持有计划和请求行锁；人员按 ID 顺序锁定并重查当前资格，使用 READ_COMMITTED；重查原班次版本、取消、计划状态及重叠。
- 接受新增临时覆盖，原班次不动；覆盖、决策和两条审计同事务提交或回滚。
- 进行中的请求从锁等待后数据库时间向上取整秒生效；过期拒绝接受，不伪造自动 EXPIRED 状态，不重写旧 Incident 路由。
- 读接口最多 200 条并返回截断标志及数据库时间；过期判断以返回时间与 endsAt 比较，非后台自动过期任务。

## 首轮失败与修正

本地定向首轮 14 项：13 通过、1 失败。正在进行的接班测试验证当前值班已切换后，却断言第二条告警的路由应变成李娜；实际仍为张伟。检查真实接入代码确认，同服务/严重度的两小时聚合把第二条告警关联到原 Incident，旧路由保持不变正是要求，不能据此改写业务代码。

# V1.7 checkpoint-10：Redis Streams Outbox Relay

日期：2026-09-09。状态：已实现，真实 Redis CI 待验。

## 行为与配置

`AGENT_OUTBOX_ENABLED=true` 同时启用 outbox 写入与独立单线程 relay；默认 false。本机演示不要求 Redis，也不启用 Redis 健康依赖。Redis 地址、端口、密码使用 Spring 标准 `SPRING_DATA_REDIS_HOST/PORT/PASSWORD` 配置，Stream 键使用 `AGENT_EVENT_REDIS_STREAM`，默认 `opspilot:agent-events`。连接/命令默认超时 2 秒。

每秒领取一条、租约 30 秒，独立调度线程不阻塞调查执行器与其他定时任务。网络 XADD 在领取返回之后执行，通知仅包含 schemaVersion/runId/eventId；Redis 自动生成传输 ID。收到确认才写 DELIVERED；运行时错误退回 PENDING，重试间隔 1/2/4/8/16/32/60 秒，上限 60 秒。失去租约不能确认，保留可重领状态。数据库确认失败可能导致重复通知，eventId 保持不变，不承诺恰好一次。

## 验证

本地新增依赖与测试编译通过，事务/租约 6 项回归通过。本机 Docker 引擎不可用，真实 Redis 交给独立 `Redis Streams relay integration` CI；容器烟测依赖该新门禁，原有前端、H2、MySQL 门禁保留。

Redis Testcontainers 场景：真实 WRONGTYPE 拒绝 XADD 后记录保持 PENDING 并增加尝试次数；纠正 Redis 键并推进待重试时间后成功 DELIVERED，读取 Stream 校验只有三个标识字段。随后通过测试重置确认状态模拟“发送成功但未确认”窗口，重发后 Redis ID 不同但 eventId/字段一致。此场景是故障窗口状态模拟，不是进程 kill 实验。测试手工调用真实 tick，调度初始延迟设为一小时以排除后台抢占；尚无自动定时触发的时序证明。

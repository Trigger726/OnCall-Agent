# V1.8 CP07：手册级检索预算与分层固定题集

## 本轮目标和边界

接续 CP06，修复助手 Top 3 被同一多章节手册占满的问题，并用更广的固定题集比较旧/新 Demo。未回补原版全部接口或神经 reranker，不声称商业平台能力平齐。

2026-10-15 最终状态：当前代码 158 项相关 Java、290 项 Node、H2/MySQL 共 24 项共享契约与同题同语料旧/新整包实页均通过。早期“148 项/待整包”是本轮中断前阶段记录，现已用包含最新身份修复的源码与 Demo 重验；不代表长期目标全部完成。

## 已复现与最小修复

旧源码在 35 个匹配章节（超过 candidate-window=20）的样本中，三个返回项均为 `diversity-long`，第二、第三份相关手册被挤掉。实际 Recall@3 为 0.333333。四个失败分别覆盖 BM25、真实语义索引/RRF 接线、范围/ACL/发布围栏和固定评测。

- BM25 和语义排序在候选窗口截断前，每份可见手册保留最高排名片段；其他相关手册不会被同一本书的多章节耗尽窗口。
- RRF 仍按片段 ID 融合，不伪称神经 rerank 或手册级 RRF；融合完整双路窗口后再次按文档去重，最后取 Top K。
- 仍先做 PUBLISHED、当前角色 ACL 和服务器推导的 Incident 范围过滤。排序不增加跨服务回退，不修改 CMDB 扩展策略。
- 返回真实选中片段的引用、heading、excerpt、rank/score；未拼造引用。原 BM25 公式、向量模型、RRF rankConstant 和稳定 tie-break 不变。
- `DOCUMENT_DIVERSITY_V1` 写入评测说明和 datasetVersion 输入，历史评测/请求回执不重写；搜索 warnings 保持真实降级/范围含义。

首次 148 项回归曾有 1 项失败：把正常结果粒度放入 warnings 破坏了原 `warnings=[]` 契约。已移至评测说明，保留失败 XML，不修改旧断言来掩盖问题。

按 `karpathy-guidelines` 先复现再修复；按 `frontend-testing-debugging` 验证实际页面和交互，Browser skill 不可用时复用已有 Playwright 1.63.0/Chrome，不新增浏览器依赖。

## 固定题集和度量

[固定题集](../../scripts/fixtures/runbook-document-diversity-cases.json)：六份未改种子手册＋四份独立发布的多章节受控手册，另有一份管理员私有手册和一份未发布候选。32 题分四层，各 8 题：关键词、症状/任务、Incident 范围、负例围栏。

标签在查看整包结果前声明；算法来自之前四个重复片段复现场景，不按这 32 题调权重。标签是工程作者的主题判断，不是用户日志、独立人工研究或盲测留出集。

24 个有正例问题报告 Hit@3、真正的 Recall@3、MRR、固定三位置 Precision@3 与等权 NDCG@3；重复文档不能重复贡献召回/DCG，仍消耗原排名位置。8 个负例单独报告，不算作“完美相关性”。分层结果、每题实际引用和完整数据集/语料哈希必须保存，不能只展示有利汇总。

参考 [Elastic 官方排名评测](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/search-rank-eval)对典型问题和相关性标签的分离；[RRF 官方说明](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/reciprocal-rank-fusion)仅支持融合方法，不证明本项目排序质量。

## 3. 数据与生命周期

Flyway V6 为 `agent_investigation_run` 增加：

- 同一 Incident 唯一的 `idempotency_key`。
- `deadline_at` 与终止请求的类型、时间、申请人、原因。
- 由数据库事务串行分配的 `next_event_sequence`。
- 面向运行状态和截止时间的索引。

当前终态包括 `COMPLETED / PARTIAL / FAILED / CANCELLED / TIMED_OUT / QUEUE_REJECTED`。取消和超时先写请求事件，再由执行线程在安全边界持久化最终事件；终态不会生成新的报告或处置提案。

## 5. 真实页面验收

验收环境使用独立的 `http://localhost:9910`、空 H2 内存库和一个延迟响应的本地 Prometheus 替身，不改动正常 9900 环境或用户数据。延迟 Provider 用于稳定制造可取消窗口。

### 5.1 Incident 工作台

1. 登录本地演示账号并进入 `/incidents?selected=1`。
2. 点击“运行 Agent 调查”，确认“取消 Agent 调查”立即出现且可用。
3. 显式取消后，持久化 run 为 `CANCELLED`，报告数量和处置提案数量均未增加。
4. 页面最终显示“调查运行 #1 已取消”和“Agent 调查 #1 已取消”，不保留 `network error`。
5. 默认桌面视图与 390 x 844 视口均无空白、遮挡阻断或控制台错误。

### 5.2 OnCall 助手

1. 创建绑定同一 Incident 的协作会话。
2. 运行调查后确认“取消”按钮可用并提交取消。
3. 上下文轨迹回填 `RUN #1 / CANCELLED`，页面没有错误提示。
4. 再次运行产生 `LIVE RUN #2`，证明上一终态的浏览器幂等键已清理；取消后 `RUN #2` 同样为 `CANCELLED`。

### 5.3 实页测试发现并修复的问题

- 运行时主按钮曾被通用 `actionLoading` 禁用，导致取消入口不可点击；已拆分运行控制禁用条件。
- 工具返回与取消同时发生时，终止异常曾被工具失败分支误捕获，并尝试重复写入同一步骤序号；已让终止异常直接越过工具失败处理，并新增专门集成测试。
- 取消期间 SSE 连接异常结束时，页面曾只显示传输错误且不刷新已落库终态；两个入口现都会以服务端 run 为事实源重新对账。
- 异常断流后浏览器端幂等键曾残留，使下一次运行回放已取消 run；持久化终态确认后现会清理键并为下一次运行生成新键。

## 6. 配置与接口

运行控制默认配置：

- `AGENT_EXECUTION_TIMEOUT=60s`
- `AGENT_MAX_EXECUTION_TIMEOUT=5m`
- `AGENT_CORE_POOL_SIZE=2`
- `AGENT_MAX_POOL_SIZE=4`
- `AGENT_QUEUE_CAPACITY=50`

接口变化：

- `POST /api/v1/incidents/{id}/investigations/stream?timeoutMs=...` 接收 `Idempotency-Key`。
- 响应头返回 `X-OpsPilot-Run-Id` 与 `X-OpsPilot-Idempotent-Replay`。
- `POST /api/v1/agent-runs/{runId}/cancel` 接收可选取消原因。

## 7. 当前边界

- 幂等重试会返回已持久化的 run 快照和游标回放能力；当前不是多订阅者实时广播，也不覆盖多实例内存任务协调。
- `Future.cancel(true)` 是尽力中断。不能响应线程中断的外部客户端仍由其连接/读取超时限制单步阻塞时间，随后在执行边界进入取消或超时终态。
- 队列拒绝以已持久化 run 和 SSE `RUN_REJECTED` 表达，流式请求本身不改成 HTTP 503；前端将该终态呈现为“队列已饱和”。
- H2/MySQL 兼容迁移已通过 H2 回归，真实 MySQL Testcontainers 尚未接入。
- GitHub Actions、镜像构建流水线、SSE 强制断线和更多并发故障注入留到 V1.5 后续检查点。

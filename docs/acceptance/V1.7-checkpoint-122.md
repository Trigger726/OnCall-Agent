## 七步共享链路与权威证据

现有H2和新的显式MySQL入口使用同一业务场景/断言，没有删改原七个case名称：

| 阶段 | 所证明的行为 |
| --- | --- |
| 旧V40有数据 | 原计划成员操作、开放申请与冻结候选真实HTTP产生，无投递适配器 |
| V40→V41、默认关闭 | 原40迁移记录和业务指纹相同，不回填旧发布、不生成关闭期间发布的通知 |
| 启用但未调度 | 先持久PENDING0；随后授权新候选不改原冻结收件人 |
| 真实503后关闭 | 原事件PENDING1/HTTP503、payload/key持久化，而非内存等待 |
| 重启真实200 | 同一原key/相同载荷送达，申请仍OPEN，不自动替人接班 |
| 撤权再重启 | 原候选不再合格则SKIPPED/NO_LONGER_ELIGIBLE，无新HTTP改投 |
| 原键回放与人工认领 | 回放不重发；最后明确人的claim才生成覆盖，通知回执仍保留 |

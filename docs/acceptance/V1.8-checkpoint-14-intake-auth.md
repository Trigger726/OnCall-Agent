## 行为与兼容迁移

- `POST /api/v1/alerts/intake` 要求有效 Bearer 会话，允许当前 `ADMIN / OPS_MANAGER / ON_CALL`。匿名、无效/过期/撤销会话、停用账户返回 401；有效 `AUDITOR` 返回 403。授权前即拒绝匿名非法 JSON。当前角色来自数据库，旧 JWT 不会保留已撤销的写入角色。
- 控制器在 READ_COMMITTED 事务中锁定并复核账户状态、认证版本、当前角色和会话有效期；沿用现有 SessionAuthorization，不新增认证机制。保留 AlertService 原有去重、幂等、升级路由及事务隔离约定。
- 每次成功授权调用新增 `ALERT_INTAKE / ALERT_EVENT` 审计，记录当前操作者与目标 ID。详情仅包含服务端生成的动作和 Incident ID，不保存 Authorization、请求正文或 labels；审计与业务一起提交，审计异常则告警、Incident、时间线与审计共同回滚。
- 同外部 ID、同状态重试保持 `REPLAYED`、原 ID 与 occurrence=1，不新增业务事实；**本次调用仍新增一条操作者审计**，不再声称该兼容端点重试对整个数据库零写入。Alertmanager 原有重试口径不变。
- 正式 `/integrations/alertmanager/webhook` 继续独立 Secret 校验，不要求用户 JWT；用户 JWT 也不能替代 Secret。持续机器投递优先使用它。旧兼容客户端需要登录再发送 Bearer。

同步给既有 API/Problem 成功用例补合法身份；Tracing pipeline 把原有登录移到 intake 前并携带 Bearer；轮转实页夹具显式填写隔离测试账户，不再依赖已删除的登录自动填充。没有放开测试专用认证旁路。

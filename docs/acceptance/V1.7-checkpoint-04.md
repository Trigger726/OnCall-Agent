## 5. 并发证据范围复核

当前 `ProblemCreationConcurrencyIntegrationTest` 使用 H2；`MySqlCompatibilityIntegrationTest` 对 Problem 创建、已知错误、解决执行顺序调用。因此已有绿色 CI 证明 MySQL 的迁移、长标题与生命周期，尚不能证明 MySQL 双事务同时提升候选的行为。

源码风险点：`create` 先查询记录，再插入，捕获唯一键冲突后再次普通查询。依据 [MySQL 8.4 一致性读说明](https://dev.mysql.com/doc/refman/8.4/en/innodb-consistent-read.html)，REPEATABLE READ 中普通查询可能继续使用旧快照。由此推断，竞争失败者可能不能立即读取另一事务刚提交的 Problem；此处是待复现风险，尚未取得失败实测，不作为已确认缺陷。

下一轮验证应让两个真实 MySQL 事务都完成首次“记录不存在”查询后再放行创建，要求恰好一次创建、一次复用、同一主键、关联与时间线不重复，并为屏障和 Future 设置等待上限。需要同时覆盖独立提交，不能用外层测试事务回滚掩盖提交时序。本机 Docker daemon 当前不可用，可由已有 Linux CI 的 MySQL 门禁执行该用例。

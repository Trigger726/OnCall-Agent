- 日期：2026-09-05

- 状态：本地全量测试与 JAR 通过，最终 MySQL 与远端交付待验。

## 1. 自检发现与失败证据

checkpoint 03 已上传且四段式 CI 成功。继续检查输入边界发现：CMDB 服务名允许 128 字，告警标题允许 240 字，但新 Problem 标题直接拼接服务名、分隔文字和告警标题，可能达到 374 字，超过 `problem_record.title VARCHAR(240)`。

新增 `shouldPromoteMaximumLengthEvidenceWithoutLosingOriginalTitles`，构造两条同指纹事故，将源服务名和告警标题分别设到合法上限，经真实 MVC 登记接口复现 HTTP 500。数据库明确报告标题长度 374 超过 240；该失败发生在修复前，不属于环境故障。

## 2. 修复与验证

- 仅限制自动生成的摘要标题；超长时保留前缀并追加省略号，总长度不超过 240 个 UTF-16 单元，切点避开代理对中间。
- 保留源服务名、告警标题、指纹和两条 Incident 关联。摘要截短不改变候选匹配或原始证据。
- H2 回归断言接口成功、摘要长度与省略号、保留服务名、两条关联、两份完整告警标题。
- 全量 `mvnw -B package`：41 项测试，40 通过，0 失败，0 错误，1 条 MySQL 条件测试按设计跳过；可执行 JAR 打包成功。
- MySQL 8.4 集成场景增加相同上限输入和证据保留断言，远端执行结果待补。其余 Problem 生命周期仍保留验证。
- 本次没有前端修改；checkpoint 03 的桌面/移动交互证据保持原有范围，本次新增证据来自服务端测试与打包。

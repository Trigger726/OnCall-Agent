# V1.7 checkpoint-24：Provider W3C Trace Context 传播

日期：2026-09-18。状态：部分通过。本地协议级集成测试、86 项后端回归和可执行 JAR 打包已通过；远端七项 GitHub Actions 尚待本次提交复验。V1.7 整体仍在持续迭代。

## 本轮问题与失败证据

checkpoint-21～23 已证明 OpsPilot 进程内的 `HTTP -> agent.run -> agent.tool -> provider.query` 层级、真实 OTLP/Tempo 存储和短暂故障恢复，但 Provider 自己通过 `RestClient.builder()` 创建客户端，绕过 Spring Boot 自动配置的 observation/tracing customizer。新增测试先在一个 sampled root 下分别调用 Prometheus 与 Loki，两个真实本机 HTTP 端点收到的 `traceparent` 均为 `null`，断言以 `Expecting not blank but was: null` 失败。

这条红测把问题限定为“业务 Provider span 已存在，但出站 HTTP 上下文没有真正越过进程边界”，避免把 Tempo 中可见的单服务 span 误称为跨服务传播。

## 实现

- `PrometheusMetricsProvider` 与 `LokiLogsProvider` 构造器注入 Spring Boot 提供的 prototype `RestClient.Builder`，在保留各自 base URL、连接/读取超时、Loki 租户头与 Bearer Token 的前提下构建客户端。
- 不在业务代码手写 `traceparent`，由 Micrometer Observation/OpenTelemetry instrumentation 创建标准 HTTP client span 并注入 W3C 上下文，采样与 propagation 配置继续由框架统一管理。
- 原有 Provider 契约测试显式传入普通 builder，继续验证 URI、查询参数、请求头和响应映射，防止 tracing 修复改变业务协议。

## 可证伪验收契约

`HttpTracePropagationIntegrationTest` 使用真实 TCP `HttpServer` 暴露 Prometheus `/api/v1/query` 与 Loki `/loki/api/v1/query_range`：

1. 在同一个 sampled root span 下，经真实 `OpsPilotTracing.traceProviderQuery` 分别调用两个 Provider。
2. 两个下游必须收到格式为 `00-<32 位 root traceId>-<16 位 client spanId>-01` 的 W3C `traceparent`，且 client spanId 不能等于 root spanId 或全零。
3. 真实 SDK exporter 必须恰好捕获两个 `opspilot.provider.query` span，二者 parent 都是 root。
4. 必须恰好捕获两个 `SpanKind.CLIENT` span，每个 parent 都属于上述 Provider span。
5. 两个 HTTP header 中的 spanId 必须与两个已导出的 client span ID 一一对应，不能只验证“有一个看起来像 header 的字符串”。

## 边界

- 本轮的两个下游是本机真实 TCP HTTP 端点，不是生产 Prometheus/Loki 集群；未验证 TLS、代理、多租户网关或真实服务端 instrumentation。
- 已证明 OpsPilot 正确发出 W3C context，但尚未证明下游创建 server span 并与 OpsPilot trace 在 Tempo 中拼接。
- 未验证 baggage 传播、跨信任边界 header 过滤、不同采样策略的一致性、高并发开销和生产容量。
- checkpoint-23 的 Collector 存活前提和内存队列边界不变，不声明 Collector 重启后零丢失。

## 依据

- [Spring Boot 3.2 RestClient](https://docs.spring.io/spring-boot/docs/3.2.3/reference/htmlsingle/#io.rest-client.restclient)：建议注入自动配置的 `RestClient.Builder`；直接静态创建不会应用 Boot customizer。
- [Spring Boot Actuator metrics - RestClient](https://docs.spring.io/spring-boot/reference/actuator/metrics.html#actuator.metrics.supported.http-clients)：使用自动配置 builder 才能获得客户端 instrumentation。
- [Spring Boot 3.2 application properties](https://docs.spring.io/spring-boot/docs/3.2.12/reference/html/application-properties.html#application-properties.actuator.management.tracing.propagation.produce)：W3C 是出站 propagation 的默认格式。
